**Rationale for `Tool: none`:** `components.json` does not exist and the project already has a complete, consistently-applied dark "terminal/cyber" component library used across every existing panel, header and input in the app (verified by direct reads of `app/components/ui/*` and `app/components/panels/*`). CLAUDE.md's "no upstream branding, ever" rule and the project's own 2026-09-25 declutter (which *removed* CRT/glitch chrome rather than adding new visual systems) both signal that this phase must extend the existing system, not introduce a second one. Every new control this phase adds (base picker, region legend isolate/mute, label-scheme controls, packer toggle) is specified below in terms of the *existing* primitives.

## Spacing Scale

This codebase does not use the generic Tailwind 8-point scale in isolation — it is a dense, information-heavy terminal UI built mostly on multiples of **2px**, with 4px as the practical minimum unit. Declared values (verified against `app/components/ui/*`, `app/components/panels/shared.tsx`, `app/globals.css`):

| Token | Value | Usage |
|-------|-------|-------|
| hairline | 2px | Row vertical padding (`PanelRow` `py-0.5`), tri-bar stroke gaps, `mt-0.5` micro-offsets |
| xs | 4px | Icon-to-label gaps (`gap-1`), tight inline padding |
| sm | 6px | Chip/pill padding (`px-1.5`), popover-trigger padding, `gap-1.5` |
| sm+ | 8px | Standard row/column gap (`gap-2`), header vertical padding (`py-1.5`→~6px is actually sm, but 8px is the dominant "gap-2" value used between header boxes) |
| md | 10-12px | Panel/header horizontal padding (`px-2.5`, `px-3`), input vertical padding |
| lg | 16px | New-in-this-phase section gaps (base-picker's internal row stack, region-legend row-to-row breaks if grouped) |
| xl | 24px | Max gap between unrelated header clusters; outer page margins |

**Deliberate exception — established 2px-based density scale (pre-existing, project-wide, not invented for this phase):** the `hairline` (2px), `sm` (6px), and `md` (10-12px) tokens above are not multiples of 4 and are not values on the generic 8-point scale (4/8/16/24/32/48/64). They are this codebase's actual, shipped spacing convention — a 2px-based density scale (2 / 4 / 6 / 8 / 10-12 / 16 / 24px) already in production before this phase, verified directly in `app/components/ui/*` (e.g. `CyberButton`/`Pill` chip padding at `px-1.5` = 6px, `CyberInput` internal spacing) and `app/components/panels/shared.tsx` (`PanelRow`'s `py-0.5` = 2px row padding, `PanelColorBar` gaps, `px-2.5` = 10px panel/header padding). This is a project-wide, deliberate, already-in-production density choice — not a new one-off exception being invented for Phase 4's new components. Phase 4 extends this existing convention rather than introducing a competing, purer 4px-multiple scale, because a stricter 4px scale would visually contradict every existing panel, header, and control the new base picker and region legend sit directly beside. Accordingly, the new components this phase adds — the base picker's rows/chips/steppers and the region legend's rows/buttons — use these same `hairline`/`xs`/`sm`/`sm+`/`md` tokens for their internal padding and gaps (not a rounded-up 4px equivalent), except where the 24px hit-target exception below explicitly overrides them for interactive touch targets.

Exceptions for this phase:
- **Minimum interactive hit target for the base-picker's own controls (numeric field, stepper buttons, chips, slider thumb) is 24px** in the shorter dimension, even though ambient list rows are far denser (rows run ~18-20px tall via `py-0.5` + 10px text). The base picker is a primary, frequently-used control (D-01/D-03), not a dense list row, so it gets a slightly larger, more forgiving target — this is the one deliberate deviation from the ambient density.
- Region-legend rows (D-20) reuse the existing dense `PanelRow`/`HoverInfoList` row height (~20px) even at base 64's 6+ rows, because D-20 explicitly asks for one continuous scrollable list, not larger touch-friendly rows — density here is a feature (see a Scrollable Region Legend below), not a hit-target concern (isolate/mute are two separate small buttons per row — apply the 24px minimum to *those two buttons specifically*, not to the row's overall height).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Micro-label (eyebrow) | 8-9px | 400 | 1.4 |
| Body / list text | 10-11px | 400 | 1.5 |
| Input / typed text | 14px | 400 | 1.5 |
| Display (live summary numerals) | 16px | 600 | 1.2 (leading-none) |

Declared sizes: **8px, 10px, 14px, 16px** (4 sizes, matches the ceiling). Declared weights: **400 regular** (all labels, body, list rows, helper/error text) and **600 semibold** (only the large numeral in the base picker and any other "hero number," mirroring the one existing precedent for weight 600 in this codebase: `Figure.tsx`'s `font-semibold` on its rendered value). Do not introduce a third weight.

- All new microcopy (labels, panel headers) is `uppercase`, `tracking-[0.12em]` to `tracking-[0.3em]` per the existing convention (`CyberInput` label = `text-[10px] uppercase tracking-[0.12em] text-gray-400`; panel headers = `text-[8px] uppercase tracking-[0.3em]`).
- Body text (list rows, inline messages, helper text) is sentence case, not uppercase — matches existing panel row text (`ZonesPanel`, `RegionsPanel`).
- The base picker's current-base numeral is the one Display-role element this phase introduces: 16px/600/leading-none, in `text-gray-100` (`#f3f4f6`) — **not** accent green (matches `Figure.tsx`'s own precedent: the big number is neutral white-gray, the small label around it carries the accent color).

## Base Picker Contract (D-01..D-07, UI-01)

**Placement:** a new self-contained control rendered inside `CyberPageHeader`'s existing `actions` slot (`app/NumogramClient.tsx` ~line 1520), immediately left of Undo/Redo/Share. This resolves 04-RESEARCH.md Priority 6's flagged ambiguity: the fixed-position layout-switcher `ButtonSet` and `CyberPageHeader`'s `actions` slot are two different existing elements; the base picker joins the header slot (literally "in the header," D-03), using the same chrome as every other header box (`border: 1px solid rgba(255,255,255,0.08)`, `background: rgba(8,8,15,0.94)`).

**Two-state interaction model** (this is this document's resolution of D-01's "primary, not competing" requirement):

1. **Collapsed (default, always visible):** shows only the current base as the editable numeral itself (Display role: 16px/600/`#f3f4f6`) plus a compact one-line live summary in body-role gray-400 text immediately after it, e.g.:
   `10  ·  10 zones · Warp — · TQ [1,2,4,5,7,8] · 45 demons`
   Clicking or focusing the numeral turns it into a live text cursor in the same visual slot — there is no separate "edit" affordance, the number you see is the field (matches "numeric field is primary," D-01).
2. **Expanded (on focus/click, closes on blur/Escape/outside-click):** a dropdown panel anchored below the collapsed control, using the same chrome as `CyberPopover`'s portal technique (`border: 1px solid rgba(16,255,80,0.35)`, `background: rgba(8,8,15,0.96)`), reveals three stacked rows:
   - Row 1: `[ − stepper ] [ numeric input, 16px/600 ] [ + stepper ]` — steppers are 24px hit targets, step by 2 (D-05); each stepper button carries an explicit accessible name via `aria-label` (`aria-label="Decrease base by 2"` / `aria-label="Increase base by 2"`), matching the Region Legend's Isolate/Mute button pattern below (`aria-pressed` + a described `aria-label`) rather than relying on the icon glyph alone; a small superscript hint (`×10` badge, accent green, shown only on Shift-hover per D-05's optional discretion) may appear next to the steppers if the planner adopts the larger-jump modifier, but is not required.
   - Row 2: a full-width `<input type="range">` mapped 2..1024 step 2 (matches the chip ceiling), thin track (`height: 2px`, `background: rgba(148,163,184,0.25)`), accent-green thumb, live-updating as it drags (D-04).
   - Row 3: the notable-base chip strip — horizontally scrollable (`overflow-x-auto`, inherits the project's existing thin scrollbar from `app/globals.css`), each chip a `CyberButton size="sm"` showing the literal number, `active` (green-tinted, per `CyberButton`'s existing `active` prop) when it equals the current committed base. **Final chip set (D-07): `2, 4, 6, 8, 10, 12, 16, 22, 28, 64, 80, 82, 100, 1024`** — 14 chips, in that ascending order, never reordered or grouped.
3. **Inline refusal message (D-06):** rendered as a 4th row inside the same expanded control (never a toast/banner elsewhere), 10-11px body text in `#f87171`, replacing/supplementing the live-summary line — e.g. `Base 27 is odd — numograms need an even base. Showing base 26.` The diagram/summary elsewhere on the page keeps showing the last valid base unchanged (never blanks/greys out).
4. **Debounce:** every keystroke/drag tick updates the visible numeral immediately (optimistic local text state); a 200ms debounce (per 04-RESEARCH.md Pattern 1) calls `validateBase()` before committing to the real `base` state that drives the rest of the app. This debounce window is a technical/plan detail, not a visual one — no loading spinner or visual delay indicator is needed at 200ms.

**Packer toggle (todo 005) placement:** a 4th row in the same expanded dropdown, below the chip strip, labeled `Layout: ( ) Spiral ( ) Shelf` using two `CyberRadio` instances (existing component, unmodified). Visible whenever the *current* layout is procedural (i.e., always, except when base = 10 and one of the four authored presets — original/labyrinth/ladder/planetary — is active). This is the resolution of CONTEXT.md's open discretion item "where the packer toggle fits visually."

## Zone Label Scheme Contract (D-08..D-13, UI-03)

**Default:** decimal-with-separator (D-08) at every base, using the engine's existing `formatNumeral`/`parseNumeral` output verbatim (separator is already fixed by the engine as `.`, e.g. `'1.0.1'` for 3601 at base 60 — this phase must not reinterpret or restyle that separator). This is the resolved answer to ROADMAP.md's "settle the label separator" note: it was already settled in Phase 2 and Phase 4 only consumes it.

**Mode switch control:** a small settings affordance attached to the base picker's expanded dropdown (a labeled row: `Labels: Decimal / Xeno / Custom ▾`), using `CyberRadio` for the three top-level modes (Decimal, Xeno, Custom) — matches the existing radio visual language (`checked` = accent green dot + green label, unchecked = gray).

**Xenotation mode (D-09):** selecting it replaces the shown zone-label text entirely (same display slot) — never renders as a secondary annotation next to the number. Reuses `app/lib/xenotation.ts`'s existing formatting/typography (already used in `ZonesPanel.tsx` at `text-[8px] tracking-[0.08em] text-gray-500`).

**Custom alphabet (D-10..D-12):** when "Custom" is selected, a secondary disclosure appears with:
- A row of preset chips (`CyberButton size="sm"`, same visual family as the base-picker's notable-base chips, but a visually distinct group — do not let the two chip rows blur together; separate with a `mt-1 pt-1 border-t border-white/[0.04]` divider matching the existing `RegionsPanel`/`LayersPanel` sub-group convention).
- **Locked curated preset list (resolves D-10's "2-4 to start," 04-RESEARCH.md Priority 1):**

  | Preset | Characters | Length | Construction rule |
  |--------|-----------|--------|--------------------|
  | Base62 | `0-9`, `A-Z`, `a-z` | 62 | digits, then uppercase, then lowercase, ASCII order |
  | Base64 (URL-safe) | `A-Z`, `a-z`, `0-9`, `-`, `_` | 64 | RFC 4648 URL-safe alphabet order |
  | ASCII Printable | all visible non-space ASCII | 94 | codepoints `0x21`-`0x7E` in order |
  | Latin-1 Printable | ASCII Printable + Latin-1 Supplement printable range | ~190 | ASCII Printable followed by codepoints `0xA1`-`0xFF` in order |

  All four ship (D-10 permits "2-4"; shipping all four gives every notable-base chip up to `100` full custom-label coverage without falling back to decimal, per 04-RESEARCH.md's own recommendation). None are themed/exotic Unicode blocks (project's Out-of-Scope table excludes zodiac/tarot/occult correspondence packs; plain Unicode letter/digit/symbol blocks sidestep that entirely).
- A free-text input below the presets (`CyberInput` or `CyberTextArea` with `pillCollection={false}`, single line) for a fully custom character set (D-10's "and" requirement, not "or").
- **Inline validation (D-12)**, appearing directly under the input in the `#f87171` error-role color the instant it applies (as-you-type, no submit step):
  - Duplicate character → "'{char}' repeats — every character must be unique."
  - Too short for the current base → "Needs {needed} more character(s) for base {base}."
  - Possible glyph-rendering failure (canvas heuristic vs. a Private-Use-Area reference glyph, per 04-RESEARCH.md Priority 1) → "'{char}' may not render in your browser — try a different character." This is a **heuristic warning**, not a hard block — the character remains usable (matches Assumption A2: false negatives are possible and acceptable).
- One reusable ordered character list applies across however many digits the current base needs (D-11) — there is no per-digit or per-base sub-configuration UI.

**URL codec (D-13):** the chosen mode + value round-trips through the URL as a single `labels=` param:
- `labels=xeno` — xenotation mode
- `labels=preset:base62` (or `base64url`, `ascii`, `latin1`) — a curated preset
- `labels=custom:<percent-encoded characters>` — free-text custom alphabet
- Omitted entirely when mode is the default (decimal-with-separator) — matches the existing "omit when default" convention already used for `base=10` and `layout=original`.

## Big-Base Degradation Contract (D-14..D-18, UI-02 refusal path)

**Trigger:** the moment a committed, valid base exceeds `TIER_TABLE.boundaries.svgRichMaxN.n` (currently 200) — no extra click, no "load it anyway" gate (D-14, D-18).

**Replaces:** the entire interactive `Projection.tsx` SVG tree. Two things render instead, stacked vertically in the same content area the diagram would otherwise occupy:
1. **A numeric summary card** — reuses the base picker's own live-summary data (zone count, Warp yes/no, Torque cycle lengths, demon count), but rendered larger and standalone (Display role, 16px/600, in a bordered chrome box matching `CyberCardContainer`'s existing look: `border border-[#334155] bg-[#0a1018]`).
2. **The accessible text view** (see Accessibility Contract below) — always shown together with the summary in this fallback state, not as a separate opt-in, since there is no interactive diagram to fall back from.
3. **The fallback message** (Copywriting Contract, "big-base fallback" row) directly above the summary card, in `#f87171`, reading the live cutoff number from `TIER_TABLE` (D-16) — never a hard-coded "200" string anywhere in the component.

**Not built this phase (D-17):** any visual design for the "SVG-lean" intermediate tier (`svgLeanMaxN`, currently 300). Only two effective outcomes exist in the UI: full rich SVG, or this summary+text fallback. Do not add a third visual state.

**`tier=` override (D-18):** remains a diagnostic-only URL param with no user-facing button or affordance anywhere in this contract — it is not part of any component's visible UI, only a URL-read-on-mount escape hatch for technical users.

## Region Legend Contract (D-19..D-24, UI-05)

**Row source and order:** `g.torques` (already in canonical order: length descending, then smallest zone id — no client sort), then `Plex`, then `Warp` if present (D-23: identical treatment for all rows, so ordering Plex/Warp last, after all Torque rows, is a presentation choice, not a functional one).

**Row label convention:** `Torque {letter}` using the engine's own `torqueLabel()` (A, B, C, ... then numeric past 26), `Plex`, `Warp` — never a bare index number as the primary label (stable `id` like `torque:3` is used for state/URL only, not shown to the user).

**Layout:** one continuous, scrollable list (D-20 — no grouping/collapsing behind a summary row even at 6+ rows), using the existing `HoverInfoList`/`SelectableListPanel` primitives with a `maxBodyHeight` + `overflowY: auto` (same technique `CyberPanel`'s `scrollable` prop already implements) so the panel doesn't grow unbounded as base grows.

**Row anatomy** (extends `HoverInfoListItem`, do not fork a new list primitive):
```
[ PanelColorBar (torque cyan / warp green / plex brown, per Data-Identity Palette) ]
[ Label: "Torque A" ]                                    [ Isolate ] [ Mute ]
```
- **Isolate button:** small icon-only button (new spotlight-ring icon, NumogramIcons.tsx style), 24px hit target, `aria-pressed`. Engaged state = accent green `#10ff50` fill/tint (same treatment as `CyberButton`'s existing `active` state: `bg-[#10ff50]/[0.08]` + inset green underline). Disengaged = neutral gray outline.
- **Mute button:** small icon-only button (new eye-slash/hide icon), same 24px target and `aria-pressed`. Engaged state uses the **same** accent green treatment as Isolate (not a second accent hue — see Color contract) — the two are told apart by their icon glyph and their `aria-label`/tooltip text ("Isolate this region" vs. "Mute this region"), never by color alone (UI-07 non-colour cue).
- Both are independent, multi-select toggles (D-19/D-22) — any combination of isolate/mute across any number of rows is valid; clicking one never clears another row's state.
- When a row is **muted**, its own label text additionally gets a subtle strike-through style and the row's `PanelColorBar` switches to its existing `inactiveColor` (`${color}44`, the same ~27%-alpha convention `PanelColorBar` already implements for inactive rows) — a second, non-color cue beyond the button's own state.

**Diagram-side effect:**
- **Isolate** = spotlight: the isolated region's elements render at full/normal opacity; every other element dims using `Projection.tsx`'s *existing* focus-dim opacity values (already coded for hover/pin focus, e.g. `anyFocus ? 0.03 : ...` for background rings, `dimOpacity` for currents/gates) — reuse these exact numbers, do not invent new dim levels for isolate.
- **Mute** = hard hide: the muted region's zones/edges are removed from the render tree entirely (not merely `opacity: 0`) — and correspondingly removed from the roving-tabindex sequence and ARIA tree (Accessibility Contract), since D-19 specifies muted elements "disappear from view entirely," which for a keyboard/screen-reader user must also mean "disappear from the traversal order."

**URL codec (D-21, resolves ROADMAP's "settle `region=` syntax" note and 04-RESEARCH.md Assumption A3):** two new params, each a comma-separated list of stable region ids, extending `app/lib/shareParams.ts`'s existing allow-list pattern:
- `isolate=torque:0,warp`
- `mute=plex`
A region may appear in both lists at once (D-22: independent per-row booleans). Unknown/stale ids (e.g. `torque:5` after switching to a base with only 2 Torque cycles) are silently dropped on read, never reject the whole URL (matches the lenient-per-field recommendation in 04-RESEARCH.md's Open Question 1 — `base` itself stays the one strict/user-visible-refusal field). The legacy singular `tc=1` param keeps working exactly as today for old base-10 links (back-compat) but is not extended to the new multi-cycle model.

## Accessibility Contract (UI-07)

**Keyboard traversal:** roving-tabindex composite widget pattern (04-RESEARCH.md Pattern 3) — the diagram is one Tab stop; arrow keys move a single logical focus among interactive elements (zones, then syzygies/currents/gates); the focused element gets `tabIndex={0}`, all others `tabIndex={-1}`. Muted elements (Region Legend, above) are excluded from this sequence entirely.

**ARIA:** every focusable diagram element gets `role="button"` (or `role="group"` for the whole diagram) plus an accessible name built from the in-base numeral, not the raw integer — e.g. `aria-label="Zone {formatNumeral(z, base)}"`, `aria-pressed` for selection state. The base-picker's numeral input gets `aria-label="Base"` with the live summary exposed via `aria-describedby` pointing at the summary line's own id. The base-picker's stepper buttons each get an explicit `aria-label` ("Decrease base by 2" / "Increase base by 2") rather than relying on their icon glyph, matching the Region Legend's Isolate/Mute `aria-pressed` + described-`aria-label` pattern above.

**Non-colour cues:** every state this contract assigns a color to (region identity, isolate/mute engagement, error/refusal) also carries a text label or distinct icon glyph, per the specific call-outs above — never rely on hue alone anywhere in this phase's new surfaces.

**Reduced motion:** `window.matchMedia('(prefers-reduced-motion: reduce)')` (with a `change` listener) must gate the JS `requestAnimationFrame` tweens in `useTween.ts`/`engine/layout/tween.ts`'s consumer and `useOrbitalAnimation.ts`, short-circuiting to the end state instantly — the existing CSS-only `@media (prefers-reduced-motion: reduce)` block in `app/globals.css` does not reach these (04-RESEARCH.md Pitfall 3). No new visual state is needed here beyond "the tween never visibly plays."

**Digit-key shortcut (Pitfall 4 / Assumption A4):** the existing `0`-`9` gate-selection keyboard shortcut stays, unchanged, base-10-only (`if (base === 10)`) — it is not extended or generalized, and it is not removed. Document this explicitly in `ShortcutsModal.tsx`'s copy if that modal is touched this phase (e.g. "Gate shortcuts (0-9): base 10 only").

**Text view + copy (D-14's fallback and UI-07's general requirement):** a monospace, read-only text block (reuse `.ui-terminal-input`-style presentation, not an editable field) listing, at minimum: base, zone count, Warp yes/no, each Torque cycle's zones, and the demon count — using the same in-base numeral formatting as the diagram (never raw decimal integers if the active label scheme is xeno/custom). One **"Copy numogram text"** button (Copywriting Contract's Primary CTA) directly above or below the block, using `navigator.clipboard.writeText`; on success the button label swaps to "Copied" for ~1.5s then reverts — no toast, no modal, matching this project's no-modal precedent.
