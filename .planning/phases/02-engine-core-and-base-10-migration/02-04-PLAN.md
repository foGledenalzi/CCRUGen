Math (verbatim, from PROJECT.md and ARCHITECTURE.md): zones 0..n-1; pair id = low zone lo, hi = n - 1 - lo; the current of pair hi::lo flows to zone hi - lo = n - 1 - 2*lo (always odd); next pair = pairOf(n - 1 - 2*lo) = (d < n/2 ? d : n - 1 - d); the pair map is a permutation whose cycles are the regions; Plex is the fixed pair {0, n-1} (always); Warp is the other fixed pair {o, 2o}, which exists iff n = 3o + 1 with o odd (derive it from the fixed point, use the formula only as a test oracle); every other cycle is a Torque cycle (there can be many: 1,290,870 at 2^26). Gate: k -> digitalRoot(T(k), n) with `T === 0 ? 0 : ((T - 1) % (n - 1)) + 1`. The walk of a cycle alternates the odd member and the even member of each pair in flow order (base 10 Torque: 1, 8, 7, 2, 5, 4).

Measured by the planner (prototype, not committed): at 2^26 the permutation has 1,290,872 cycles; a typed-array build with a stable counting sort took about 0.6 s; retained typed arrays are about 283 MB. Per-cycle JS objects must NOT be created eagerly.

export const NUMOGRAM_CACHE_LIMITS: Readonly<{ entries: 4; zones: 67108864 }>
export function createNumogram(base: number): Numogram

export interface NumogramInternals { readonly flow: Int32Array; readonly pairCycle: Int32Array; readonly first: Int32Array; readonly length: Int32Array; readonly offset: Int32Array; readonly torqueCount: number; readonly plexId: number; readonly warpId: number }

Construction (O(n), no per-cycle objects), `P = base / 2`, `n1 = base - 1`, `next(p) = { const d = n1 - 2 * p; return d < P ? d : n1 - d }`:
1. `assertBase(base)` first (before any allocation).
2. `seen = new Uint8Array(P)`, `flow = new Int32Array(P)`, `pairCycle = new Int32Array(P)`. Discovery: for p = 0..P-1 ascending, if !seen[p], walk q = p marking seen until reaching a seen pair, counting L; store the discovered cycle as `flow[k] = p` (first pair; it is the cycle's smallest pair because every smaller pair is already seen) and `pairCycle[k] = L` (both arrays used as temporaries), k++, track maxLen. (If a walk ever exceeds P steps, throw Error('internal: pair map is not a permutation').)
3. Stable counting sort by length descending (ties keep ascending first pair = discovery order): bucket counts over 1..maxLen, start offsets from maxLen down to 1, then copy every discovered (first, length) into new `first = new Int32Array(k)` and `length = new Int32Array(k)` at its bucket position. All k temporaries are consumed before step 4 overwrites flow and pairCycle.
4. `offset = new Int32Array(k)`; o = 0; for c = 0..k-1: `offset[c] = o`; q = first[c]; repeat length[c] times: `flow[o++] = q; pairCycle[q] = c; q = next(q)`.
5. Length-1 cycles sort last in ascending first pair: if the last cycle has length 1 and first != 0 it is the Warp (`warpId = k - 1`, `plexId = k - 2`), else `warpId = -1`, `plexId = k - 1`; assert `first[plexId] === 0`; `torqueCount = plexId`; assert every Torque cycle has length >= 2 (throw Error('internal: ...') otherwise).
6. `storageBytes` = sum of byteLength of flow, pairCycle, first, length, offset.
Object model: a class with `#private` typed arrays whose instance is `Object.freeze(this)` at the end of the constructor (private fields stay writable, so lazy caches use private fields). Getters on the prototype: `cycles` materializes once a frozen array of frozen Cycle views (O(cycleCount), documented "meant for small n"); `torques` = frozen `cycles.slice(0, torqueCount)`. `plex` and `warp` views are built in the constructor. `cycleAt(id)` returns the materialized element if `cycles` was already built, else a new frozen view (views are value objects: compare by `id`, never by identity). Cycle view (class, prototype methods, frozen): `kind` = id < torqueCount ? 'torque' : id === plexId ? 'plex' : 'warp'; `torqueIndex` = id < torqueCount ? id : -1; `pairAt(i)` = flow[offset + i]; `zoneAt(i)`: pair = pairAt(Math.floor(i / 2)), lo = pair, hi = n1 - pair, odd = lo % 2 === 1 ? lo : hi, even = the other; return i % 2 === 0 ? odd : even; `pairs()`/`zones()` return fresh Int32Array copies.
Methods: `partner(z) = n1 - z`, `pairOf(z) = Math.min(z, n1 - z)`, `pair(id)`, `current(p) = { pair: p, lo: p, hi: n1 - p, to: n1 - 2 * p }`, `nextPair(p)`, `gate(k) = { from: k, to: digitalRoot(triangular(k), base), cumulation: triangular(k) }`, `cycleOfPair(p) = cycleAt(pairCycle[p])`, `cycleOfZone(z) = cycleOfPair(pairOf(z))`. Every index argument is validated (integer, in range) with a RangeError naming the argument and the valid range.
Cache: module-level `Map<number, Numogram>` used as an LRU (hit: delete + set; insert: evict the oldest while `size >= 4` or cachedZones + base > 67108864). `clearNumogramCache()` empties it.
