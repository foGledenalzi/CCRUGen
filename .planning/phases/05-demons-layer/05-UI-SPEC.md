> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — no `components.json` anywhere in the repo; `tailwind.config.ts` has an empty `theme.extend`, meaning every value in the app is a Tailwind arbitrary literal (`text-[9px]`, `w-[580px]`) or an inline `style`. shadcn was deliberately **not** introduced: this is Phase 5 of an 8-phase, 47-plan-deep project with a fully hand-built "Cyber" terminal design system already shipped across Phases 1–4. Initializing shadcn now would mean re-skinning `CyberPanel`, `CyberButton`, `InfoDisplay`, four layout renderers and the region legend for no product benefit — the reasonable call is to extend the existing system, not fork it. |
| Preset | not applicable |
| Component library | Custom, hand-rolled, in `app/components/ui/`: `CyberPanel` (collapsible/draggable panel shell), `CyberPanelHeader`, `CyberButton`, `CyberButtonGroup` (segmented control), `CyberInput` (terminal underline field), `CyberRadio`, `CyberCheckbox`, `CyberTextArea`, `CyberPopover`, `Pill` (chip), `DataRow` (label/value line), `SectionFrame` (bordered sub-block), `StatusDot`, `GlitchText` (bold accent title), plus domain components `HoverInfoList`/`PanelGroup` (`app/components/panels/`). **Phase 5 reuses these; it does not introduce a second component vocabulary.** |
| Icon library | None from npm. Hand-drawn inline SVG in `app/components/numogram/NumogramIcons.tsx`: `viewBox="0 0 24 24"`, stroke-only (`fill="none"` + a low-opacity solid accent dot), one `clr` color prop, sized either 18×18 (primary view/layout icons: `RingIcon`, `SpiralIcon`, `PairGraphIcon`, `IsolateIcon`, `MuteIcon`, `ZoomInIcon`, `FitIcon`) or 12×12–14×14 (secondary toolbar icons: `UndoIcon`, `RedoIcon`, `ShareIcon`). Phase 5 adds one new icon to this file (`DemonsIcon`, spec below) — no new icon package. |
| Font | `ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, "Liberation Mono", "Courier New", monospace` (`app/globals.css` `.ui-terminal-input`; `font-mono` utility class used everywhere else). There is no non-monospace font anywhere in the app. Phase 5 introduces zero new typefaces. |

## Layout Contract

### Entry point
A new icon-only button in the header actions row (`app/NumogramClient.tsx`, same `<div className="flex flex-wrap items-center gap-1">` as `BasePicker`/Undo/Redo/Share), placed **after** the Share button:
- Visual: identical box treatment to Undo/Redo/Share — `px-1.5 py-1`, `border: 1px solid rgba(107,114,128,0.35)`, `background: rgba(107,114,128,0.06)`, icon color `#6b7280`.
- Active (overlay open): border `rgba(16,255,80,0.35)`, background `rgba(16,255,80,0.08)`, icon color `#10ff50` — the exact token already used for Share's "copied" state and every other active-chrome moment in this app. Never invent a second "active" treatment.
- `title="Browse demons"`, `aria-label="Browse demons"`, `aria-pressed={open}`.
- **Icon-only, no visible text label.** The header was deliberately widened once already (Phase 4 plan 04-12, 384→480px) to just fit BasePicker + Undo/Redo/Share beside the fixed layout switcher at 1280px; a fifth control with a text label risks reopening that fit regression. The accessible name carries "Browse demons" instead.
- **Never gated behind `showDiagram`.** Base 666 (this phase's own headline example) has no SVG diagram under the current tier table — the entry point, and everything behind it, must work from `g` (the raw `Numogram`) alone, exactly like the existing Zones/Syzygies/Currents/Gates panels already do (see Research Pitfall 2).

### Overlay shell
Scaled `ShortcutsModal` pattern, not `CyberPanel`:
- Backdrop: `position: fixed; inset: 0; z-index: 80` (below `ShortcutsModal`'s 84 so the two never visually compete if ever open together), `background: rgba(0,0,0,0.62)`, dismisses on click.
- Content box: centered, `width: min(94vw, 1100px); height: min(88vh, 860px)` desktop, `width: 100vw; height: 100vh` under the existing mobile breakpoint (matches the app's existing mobile-panel-goes-full-width precedent). `border: 1px solid rgba(255,255,255,0.12); background: rgba(8,8,15,0.97)`. `font-mono` throughout.
- Header row inside the box: title "Demons" using `ShortcutsModal`'s exact title style (`text-[10px] tracking-[0.22em] uppercase`, color `#10ff50`) **plus** a live total-count `Metric` (label "Total", value `summary.demonCount.toLocaleString('en-US')`, reusing `BigBaseSummary`'s `Metric` component verbatim) to the right of the title, and a `close` button on the far right (`ShortcutsModal`'s exact close-button style: `text-[8px] uppercase tracking-[0.14em] px-2 py-1`, color `#6b7280`, `border: 1px solid rgba(107,114,128,0.35)`).
- Dismiss: backdrop click, the `close` button, or `Escape` — all three, matching `ShortcutsModal`.
- Focus trap / keyboard: `Escape` closes; `Tab` cycles inside the box (UI-07 precedent already established for the diagram's own roving-tabindex model — the overlay itself needs a conventional focus trap, not a roving one, since it's a modal).

### Internal navigation
One segmented control directly under the header, built from `CyberButtonGroup` + `CyberButton size="sm"`, three tabs: **Browser** / **Focus** / **Matrix** (exact labels, Title Case, no icons on the tabs themselves — text-only, matching every other `CyberButtonGroup` usage in the app). Default tab on open: Browser.

- **Browser tab** (DEM-01, DEM-02, DEM-05):
  - Facet chip row: `Pill`-based, `flex flex-wrap gap-2`, directly below the tab switch. 2-level disclosure — 4 top-level chips (`All`, `Chrono`, `Amphi`, `Xeno`) plus, nested/indented under whichever type chip is active, that type's subtype chips. See Color for the exact chip color rule and Copywriting for exact labels.
  - Search box: one `CyberInput`-styled field, right-aligned in the same row as the facet chips, `max-width: 220px`, placeholder exact text below.
  - Column header row: sticky to the top of the scroll area, `8px` uppercase labels (`Label` typography role), one row, four columns: `A::B` | `MESH` | `TYPE` | `NAME`.
  - Table body: `@tanstack/react-virtual`, fixed row height **22px**, row text **10px / 400 / line-height 1.4** (the `Body` role, see Typography). Row hover background `rgba(255,255,255,0.03)` (matches `CyberButton`'s own hover token). Pinned/selected row background `rgba(16,255,80,0.08)` with `box-shadow: inset 0 -1px 0 rgba(16,255,80,0.4)` — identical token to `CyberButton`'s `active` state and the region legend's Isolate/Mute active state; never invent a new selection color.
  - No zebra striping — not an established pattern anywhere else in this app (`HoverInfoList`/`DataRow` don't do it either); do not introduce it here.
- **Focus tab** (DEM-03): shows the shared focus/selection state (a highlighted zone's incident demons, or one pinned demon's chord + its two zones), with the demon detail rendered through the reused `DemonInfo` component. **Must render its own compact chord visualization independent of whether the main SVG diagram is mounted** — reusing the Pandemonium layer's chord math (not its DOM), because base 666 (the phase's own headline example) has no diagram at all above `svgRichMaxN`. This is the one place in Phase 5 where "extend, don't duplicate" needs a literal code-sharing decision at planning time, not just a visual one.
- **Matrix tab** (DEM-04): a `<canvas>` filling the remaining body height (`min-height: 400px`), plain-drag-to-pan (no modifier — unlike the main diagram's alt+drag, the matrix has no competing click-drag-to-select gesture) + scroll-wheel/pinch-to-zoom. A legend row below the canvas: four `Pill`s, one per kind (`accent` = that kind's hex, label = kind name), `gap-2`. Hover tooltip: a small floating box that follows the cursor with a 12px offset, `background: rgba(8,8,15,0.95)`, `border: 1px solid {kindColor}88`, text 10px, content `A::B · MESH · SubtypeLabel`. Click pins the same demon into the shared detail panel via the reused `DemonInfo` path.

### All-chords web ceiling (D-04)
`allChordsMaxN = 80` (measured, `engine/scene/tier-table.json`) is accepted as-is. Above n=80, the main diagram's Pandemonium "web" layer simply doesn't render (existing null-guard behavior, unchanged); this overlay's Focus/Matrix/Browser tabs are the replacement, not a second web view. No edge-bundling UI in this phase.

## Spacing Scale

Declared values (must be multiples of 4) for **layout-level** spacing introduced by Phase 5 (gaps between the overlay's major blocks, outer padding):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside a chip or tooltip |
| sm | 8px | Facet chip row gap, tab-switch-to-content gap, legend swatch gap |
| md | 16px | Overlay body inner padding, gap between the facet row and the table |
| lg | 24px | Gap between the overlay header and the tab switch; the existing 24×24px (`h-6 w-6`) icon-button touch target already established by the region legend's Isolate/Mute buttons — reused unchanged for any new icon-only buttons in this phase |
| xl | 32px | Overlay outer padding on wide desktop viewports (`>1400px`) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions: fine control-level chrome (chip padding, row height, button padding) continues the app-wide Tailwind half-step convention already in every sibling component (`px-1.5`=6px, `px-2.5`=10px, `py-[2px]`) rather than snapping to the 4px scale — e.g., `Pill` padding (`px-1.5 py-[2px]`) and the demon browser's **22px** fixed row height are both intentional non-multiples-of-4, matching the density of every other data row in this app (`DataRow`, `HoverInfoList`). Only overlay/section-level layout uses the clean scale above.

## Typography

All roles inherit the app-wide monospace stack; none are new typefaces.

### Declared for Phase 5 (new components, this phase's weight budget)

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 10px | 400 | 1.4 |
| Label | 8px | 400 | 1.2 |

- **Body (10px/400/1.4):** browser row text, facet chip text, matrix tooltip text, search placeholder, tab labels.
- **Label (8px/400/1.2, uppercase, letter-spacing 0.12–0.3em):** the browser's column headers (`A::B` / `MESH` / `TYPE` / `NAME`), the `Metric`-style total-count label ("Total"), the matrix legend labels.

Phase 5's own new components (`DemonsOverlay`, `DemonFacets`, `DemonBrowser`, `DemonFocusView`, `DemonMatrix`) use exactly **one** weight, 400, across both new roles — well inside the 2-weight maximum.

### Existing styles reused verbatim (out of scope for this phase's weight budget)

These two styles are invoked unchanged from already-shipped components. Phase 5 does not restyle, extend, or re-declare them — it calls the existing components as-is, so their weights are inherited, not newly declared, and do not count against this phase's typography budget:

| Role | Size | Weight | Line Height | Source |
|------|------|--------|-------------|--------|
| Heading | 12px | 700 | 1.2 | `GlitchText` (existing component, unchanged) |
| Display | 16px | 600 | 1.0 | `BigBaseSummary`'s `Metric` value style (existing component, unchanged) |

- **Heading (12px/700/1.2, uppercase, tracking 0.12em):** the demon's name in the detail panel (`InfoDisplay`'s `DemonInfo`, unchanged). Not a new style; do not create a second bold-heading component.
- **Display (16px/600/1.0):** the overlay header's live total-count number and, if surfaced, a per-facet count inside its chip (see Copywriting) — `text-base font-semibold leading-none text-gray-100`, `BigBaseSummary`'s `Metric` component called verbatim.

Note on weights: this app's pre-existing type system already mixes three weights (400 body, 600 `BigBaseSummary` metrics, 700 `GlitchText` headings) across components shipped in earlier phases. Phase 5 introduces **no new weight**: its own new components declare only 400, and the 600/700 values above are inherited by calling the existing `GlitchText`/`DemonInfo`/`BigBaseSummary` components unchanged rather than by re-declaring those weights for new markup. Do not introduce a weight other than 400 anywhere in this phase's new components.

## Color

### UI chrome (60/30/10)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#060609` | App background; the overlay backdrop's visible edges |
| Secondary (30%) | `rgba(8,8,15,0.94–0.97)` (~`#08080f`) | Overlay content box, browser row background, matrix canvas backdrop |
| Accent (10%) | `#10ff50` | Reserved for: the "Browse demons" header button when the overlay is open; the active Browser/Focus/Matrix tab; a pinned/selected browser row's background + inset border; the matrix's keyboard focus ring (`[data-focus-key]:focus-visible`, reused CSS rule); the copy-to-clipboard success state if any copy action is added to this panel |
| Destructive | not applicable | No destructive actions exist in Phase 5. Any future demon-row action follows the Phase 4 Isolate/Mute precedent (instant, reversible toggle, no confirmation) rather than introducing a destructive pattern |

Accent reserved for: **only** the five elements listed above. Do not tint facet chips, table rows, or matrix cells with `#10ff50` for anything other than the "currently active/selected" states named — those elements use the demon-kind taxonomy below instead.

### Demon-kind data color (separate taxonomy — do not conflate with UI accent)

This is a **second, independent** color system: semantic encoding of demon type/subtype, reused byte-for-byte from `InfoDisplay.tsx`'s existing `DemonInfo` kind-color switch. It must render identically in the facet chips, the browser's Type/Subtype column, the matrix cells, and the detail panel.

| Kind | Hex | Meaning |
|------|-----|---------|
| chrono | `#00ccff` | Both zones in a Torque cycle |
| amphi | `#cc8833` | Spans a Torque cycle and Plex/Warp |
| xeno | `#cc3333` | Both zones outside the Torque cycles |
| syzygy | `#e8e8e8` | The zones sum to `n-1` (a nine-sum-style twinning at any base) |
| (neutral / "All") | `#6b7280` | The "All" facet chip and any non-kind-specific chrome — never one of the four kind hexes |

**The one rule that prevents the taxonomy confusion the research flagged explicitly:** always derive a demon's display color via `legacyKind(subtype)` → one of the four hexes above. The engine's own `DemonType` has only 3 values (chrono/amphi/xeno) and its `DemonSubtype` has 7 (including `syzygetic-chrono` and `syzygetic-xeno`) — **do not** color a `syzygetic-chrono` subtype cyan just because its parent type chip is "Chrono." It is factually a syzygy demon and must render `#e8e8e8` everywhere (chip, column, matrix cell, detail panel), exactly as `InfoDisplay.tsx` already does today. Top-level type chips (`All`/`Chrono`/`Amphi`/`Xeno`) are the only place the 3-type names map directly to 3 of the 4 hexes (chrono→`#00ccff`, amphi→`#cc8833`, xeno→`#cc3333`); every subtype chip and every rendered demon uses the 4-way `legacyKind` mapping, not the 3-way type mapping.

### Status/error text
`#f87171` — reused verbatim from `BigBaseSummary`'s refusal-message style (`text-[11px] text-[#f87171]`). Use this, not the xeno kind color `#cc3333`, for any factual "nothing to show" or refusal-style copy in this phase (e.g., an empty search result). The two reds are visually close but semantically distinct in this app already — `#cc3333` means "this demon's kind is xeno," `#f87171` means "the system has a status message for you." Never use one for the other's purpose.

## URL State Contract (extends D-07 / `app/lib/shareParams.ts`)

Consistent with the existing lenient-per-field codec (`isolate=`/`mute=`/`labels=`):

| Param | Values | Behavior |
|-------|--------|----------|
| `demonFilter=` | one of the 3 `DemonType` or 7 `DemonSubtype` string literals (e.g. `chrono`, `cross-torque-chrono`), or omitted for "All" | Validated against the engine's exported `DEMON_TYPES`/`DEMON_SUBTYPES` tuples before calling `.group()`/`.subtype()`; an unrecognized value is dropped silently (falls back to "All"), never thrown, matching every other field in `shareParams.ts` |
| `demonFocus=` | `z:<zone>` (zone focus, e.g. `z:12`) or `<a>::<b>` (single demon focus, e.g. `12::3`) | Invalid/out-of-range values are dropped (no focus), never thrown |
| `demonsOpen=1` | present or omitted | **Recommendation, confirm at planning (D-07 left this to Claude's discretion):** include only when the overlay is open **and** a filter or focus is active, so a shared link reproduces the exact view; omit at default (closed, no filter) per the existing omit-at-default convention. If the planner decides the overlay's open/closed state itself shouldn't be shareable, drop this param and keep only `demonFilter=`/`demonFocus=` |

Matrix pan/zoom position is explicitly **not** part of the URL (D-07), matching the main diagram's own zoom/pan state.
