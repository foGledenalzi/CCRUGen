Prove REN-03 end to end in the exported site: worker scope, stale-result discarding, the computing state, responsiveness at 2^26,
the ceiling and override messages, both fallbacks, and the worker under a sub-path while offline. Add a small script that reports the

through the worker offline" means the site needs only its static files (no server, no external dependency), and an already-created
long-lived worker keeps answering with the network off. A first-ever `new Worker()` while offline fails by platform behaviour (the
browser must fetch the chunk), which is why the client creates one worker and never respawns it. The worker path is exercised at
base 28 through the existing diagnostic `?tier=canvas` override, so production behaviour at 28 stays synchronous (D-06).
