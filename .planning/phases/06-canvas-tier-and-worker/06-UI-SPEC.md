# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Read alongside:** `06-CONTEXT.md` (D-01..D-09, locked and not re-asked here), `04-UI-SPEC.md` and `05-UI-SPEC.md` (the tokens, spacing convention, copy voice and Cyber component set this phase extends). Nothing in this document restyles an existing control.

**Character of the phase:** a renderer swap. Most rows below are parity rules ("the Canvas tier draws what `Projection.tsx` and `PairGraphProjection.tsx` draw, with these named exceptions"). The genuinely new surfaces are four: (1) the Canvas diagram with its level-of-detail rules, (2) the canvas focus ring, callout and live region, (3) the computing state (dimmed previous result plus inline status), (4) the over-limit message. Everything else (panels, header, picker, text view, toolbar) is reused.

**Provenance key:** `[D-nn]` = locked in 06-CONTEXT.md. `[parity]` = copied from existing SVG-tier code that was read for this contract. `[default]` = this document's choice where CONTEXT left discretion; the planner may tune a `[default]` value without reopening the contract, but may not drop the rule.

## Design System

| Property | Value |
|----------|-------|
| Tool | none. No `components.json`; `tailwind.config.ts` has an empty `theme.extend`, so every value is a Tailwind arbitrary literal or an inline style. shadcn is not introduced (same rationale as Phase 4 and Phase 5). |
| Preset | not applicable |
| Component library | Custom, in-repo: `app/components/ui/Cyber*`, `Pill`, `StatusDot`, `app/components/panels/*`, `TextView`, `BigBaseSummary` (`Metric`), `ViewControls`. Phase 6 adds no component vocabulary; its one new drawing component is the Canvas renderer, which has no DOM chrome of its own beyond the callout chip and an `sr-only` live region (both specified below). |

## Canvas Diagram Contract

### Footprint, DPR and theming

- **Footprint:** the canvas window occupies the SVG tier's own footprint: **580 CSS px wide** on desktop `[parity, D-05]` (the SVG tier is a fixed `w-[580px] flex-shrink-0` in `Projection.tsx` and `PairGraphProjection.tsx`), height `580 x layout.height / layout.width`. Fit letterboxes the layout frame inside this window. Keeping the 580px column keeps the Selection panel's initial "right of the diagram" placement valid. **New behaviour, not parity `[default]`:** `min(580px, 100vw - 16px)` below 596px (the SVG tier has no such shrink; `BigBaseSummary` uses its own `max-w-[92vw]`) and a height clamp of at most `100vh - 96px`.
- **Backing store:** CSS size x `min(devicePixelRatio, 3)`, reduced if the area would exceed `boundaries.canvasAreaLimitPx` (read by property access from the table, never hard-coded). It covers the visible window only, never the full zoomed frame. Re-rasterize on resize and on a `devicePixelRatio` change (browser zoom, moving between monitors). Never leave a bitmap stretched by more than one frame.
- **Theming:** one dark theme. Clear to transparent, never paint a background rectangle. Forced-colors and high-contrast modes are not specially handled (same as the SVG tier). No `prefers-color-scheme` branch.
- **Scale rule:** `s = (windowCssWidth / layout.width) x zoom` CSS px per world unit. On-screen node radius `R_px = layout.nodeRadius x s`. Every width and font size below is "world value x s", then floored as stated. Zoom range: **min 0.3** (as `useCanvasZoom`), **max = max(5, 2 x labelVisibleMinRadiusPx / R_px at fit), clamped to 100** `[default]`, so a node can always reach twice the label threshold even at n = 4000 where the fitted radius is below one pixel. Wheel factor, `ViewControls` x1.25 steps and Fit behave as today; the percentage readout simply shows the larger numbers. **Planner note (checker finding):** the existing `useCanvasZoom` in `app/hooks/useCanvasPan.ts` hard-clamps zoom to 0.3-5 and is a CSS-scale plus percent-origin model for the SVG tier. The Canvas tier needs its own or a parameterized zoom state (range up to 100, with the `data-tx`/`data-ty` pan state below). The SVG tier's 0.3-5 range must not change: it is part of the frozen behaviour baseline.

### Level of detail (D-07 carried, `labelVisibleMinRadiusPx` = 7)

Read the threshold only through `labelsShown(R_px)` / `TIER_VIEW.boundaries.labelVisibleMinRadiusPx` (property access, never the whole JSON). Two states per node:

| `R_px` | Node drawn as | Hidden |
|--------|---------------|--------|
| below 7 | Disc at `max(R_px, 1.5)` CSS px: fill `${c}18`, stroke `${c}44` (idle) at `max(1, 0.7 ss s)` px. Selected/highlighted nodes keep their stronger stroke and outer ring. | Zone number, xenotation, syzygy triangle, region dot, current/gate/syzygy text |
| 7 or more | Full `Projection.tsx` node: disc, syzygy triangle (opacity 0.2 idle, 0.5 highlighted), region dot (`2k`, 0.3), bold label at `labelSize x s` | Nothing |

Further rules:
- **Hover, focus and pin override LOD for identity, not for geometry.** A hovered, keyboard-focused or pinned element is never anonymous below 7px: its name appears in the **callout chip** (Interaction Contract), not as a tiny painted label. The painted label itself still obeys the 7px rule.
- The Labels panel toggles (`numbers`, `xenotation`) keep working; LOD only hides further, it never shows what the toggle hides.
- **Region captions** (`layout.regionLabels`) follow their natural on-screen size and are hidden when it would be under **6 CSS px** `[default]`; they are exempt from the 7px zone rule so a fitted large base still shows which group is which where legible.
- **Edge text** (current name and label, gate meeting label with its plex expression, syzygy demon name) draws only for highlighted edges and only when `R_px >= 7`.

### Edges

- **Always drawn and pickable [D-04]:** syzygies and currents.
- **Gates follow `gateLayerMode(n)`:** full up to `gatesFullMaxN` 40, thin up to `gatesThinMaxN` 150, off above. In the Canvas range (202 to 4000) the table yields `off` today, so no gate draws ambiently. Keep the full and thin rules in the renderer anyway (the table may be re-measured); thin = x0.5 opacity as in the SVG.
- **Edges on demand [D-04]:** for every highlighted zone (hover, pin, keyboard focus, selection, region highlight, demon focus zones) draw that zone's **own syzygy partner edge, its current and its gate** at the Highlighted column above, even when the gate layer is off. Because selection and region highlight count, the set can be large; that is acceptable (they are drawn once per frame as plain strokes).
- **Fidelity tiers (the Canvas simplification, `[default]`):** ambient edges use simplified strokes that keep the non-colour distinction: syzygy = dotted round-cap line (`setLineDash([0.1, 3 x k s])`, width 1.5 CSS px), current = solid line, gate = dashed `5 ss / 3 ss`. Ambient currents draw an arrowhead only when their on-screen length is at least 24 CSS px. Highlighted and on-demand edges use full `[parity]` styling: graded dots on syzygies (3 to 10 dots, radius 1.0 to 2.5 k growing toward the destination), arrowheads (current 9x7, gate 8x6 marker units), the white junction or mid circle on currents (`3k` to `5k`), the two-leg and stem route geometry from `engineRenderData` unchanged.
- Route geometry always comes from the same engine routes the SVG tier consumes (`gateRoutes`, `currentRoutes`, `routePairGraph`). Canvas never recomputes routing.

### Context dimming, isolate, mute, focus modes

- **Non-selected context:** when any zone is highlighted (`anyFocus`), every edge that does not touch a highlighted zone drops to the Context column (0.08 / 0.1). Nodes do not dim on focus. This is the existing SVG behaviour, not a new look.
- **Isolate** `[parity, Phase 4]`: non-isolated zones render at 0.2 (the existing `ZONE_DIMMED` number), their edges at the Context column. **Mute** removes zones and edges from drawing entirely and from the keyboard sequence and the hit-test.
- **Demon focus** (Phase 5): the focused zone's or demon's chords draw over the dimmed diagram, width 1.2 ss, opacity 0.75, color `KIND_COLOR[legacyKind(subtype)]`, same data and same `FOCUS_CHORD_DRAW_MAX` bound as the SVG tier. The all-chords web stays off above `allChordsMaxN` 80 (so it never draws at Canvas).
- **Time Circuit** overlay draws as static edges only (`#00ccff`, 1.5 ss, 0.6), no walking dots.

### Layout notes

- **Ring, ladder, spiral:** nodes are discs; picking and ring units are zones.
- **Pair graph:** the pick and focus unit is the **pair pill** (rounded rectangle, radius `H/2`, fill `${c}` at 0.12 idle or 0.3 selected, stroke 0.9 ss idle or 1.6 ss selected), label `hi::lo` bold at `layout.labelSize`, current arcs `#22ee66` 1.4 ss with the pair-graph opacities (0.6 ambient, 0.85 highlighted, 0.08 context or pair-dimmed). LOD uses the pill's half-height as `R_px`.
- **Layout switch above `layoutTweenMaxN` 28 is instant** [D-05]: no tween, no cross-fade, but the swap passes through the Computing State when it runs in the worker.

### What does not draw on Canvas

| Feature | At the Canvas tier | Why |
|---------|--------------------|-----|
| Particles (animated carriers, selection flow, Time Circuit walkers) | Not drawn. Layers panel shows `N/A` for Particles with the info line in Copywriting. | Animation cost, and it keeps the reduced-motion story simple (Canvas has zero animation). |
| Orbit rings, planetary layout, authored base-10 presets, sphere gradients | Not drawn. They are base-10 only and base 10 never leaves the SVG tier. | Out of scope for generated bases. |
| Pandemonium all-chords web | Not drawn (Phase 5: cap 80). Focus-mode chords do draw. | Legibility cap. |

Canvas introduces **no `requestAnimationFrame` animation**: redraws happen on input and data change, coalesced to one per frame. There is no pan inertia and no zoom easing. The only motion is the CSS `opacity 0.15s` transition on the dimmed-previous-result state, which the global `prefers-reduced-motion` rule in `globals.css` already collapses to 0.01ms.

## Interaction Contract

### Picking (D-09, shared by mouse and touch)

- **Pick radius 12 CSS px** at every zoom, applied to zones and edges alike. Mouse hover uses the same rule.
- **Distance metric:** zone = `max(0, distance(cursor, centre) - R_px)` (a click on the disc is distance 0); edge = distance to its drawn polyline or curve in CSS px; pair pill = distance to its rectangle. Candidates beyond 12px are ignored. **Nearest wins.** Ties (including several at 0) resolve zone, then syzygy, then current, then gate, then demon chord, because nodes paint over edges.
- Muted and hidden elements are not candidates. Isolate-dimmed elements still are (as in the SVG).
- No disambiguation list and no magnifier [D-09]. Result latency stays inside the table's `interactionMs` (100) budget; pan frames inside `panMs` (32). Pointer-move picking is coalesced to one pick per animation frame.
- Cursor: `pointer` while a target is within the pick radius, `crosshair` otherwise (the SVG wrapper's default), `grabbing` during alt-drag pan.

### Mouse

| Input | Result |
|-------|--------|
| Hover a target | Highlight it (`onHoverInfo`), draw its on-demand edges, show the callout |
| Click a target (movement at most 3px) | Pin (`onPinInfo`; for a zone also `onZoneNodeClick`, exactly as the SVG node does) |
| Click empty space | Clear hover and pin (`clearInfoFocus`), as the SVG wrapper does |
| Drag from empty space | Rubber-band select using the existing fixed overlay and `finalizeSelection` (Shift = additive), resolving zones whose screen position falls in the rectangle through the canvas transform |
| Alt-drag or middle-drag | Pan |
| Wheel | Zoom about the cursor (existing `exp(-step x 0.0015)`, step clamped to +-100) |
| Drag that begins on a target | Ignored until release, then treated as a click only if it moved at most 3px |

### Touch (D-09)

`touch-action: none` on the canvas only (panels stay scrollable). One pointer dragging more than **8 CSS px** `[default]` pans; two pointers pinch-zoom about their midpoint and pan with it; a pointer that ends within 8px of where it began is a **tap = pin** (nearest within 12px, else clear). No hover, no rubber-band, no long-press, no double-tap zoom, no inertia. Pinch clamps to the same zoom range as the wheel. The pinch and pointer bookkeeping may follow `DemonMatrix.tsx` (pointer capture, a `Map` of active pointers).

### Callout chip

A single chip, a DOM element absolutely positioned over the canvas (not painted into it, so text stays crisp at any DPR and zoom), `pointer-events: none`, `role="tooltip"`, identical styling to the demon matrix tooltip: `background: rgba(8,8,15,0.95)`, `border: 1px solid {color}88`, text 10px / 400 / `#e5e7eb`, padding `px-1.5 py-[2px]`, `whitespace-nowrap`. `{color}` is the element's identity color from the palette above. Offset **12px** from the cursor (mouse), or from the node edge or edge midpoint (keyboard, pin). It flips to the opposite side when it would leave the canvas window.

- **Priority:** hover target, else keyboard-ring target, else the pinned element. Never more than one chip.
- **Content (no new element strings; the exact existing `aria-label` formats):** zone `Zone {label}, {Region}`; syzygy `Syzygy {a}::{b}` (zone layouts) or `Syzygy {hi}::{lo}` (pair graph); current `Current {name}: {label}`; gate `Gate {name}: zone {from} to zone {to}`. The `, selected` suffix is added in announcements only, not in the chip (selection is visible on the node).
- On touch, the chip for a tapped element persists until the next tap or a clear. It is the only on-canvas confirmation that a tap landed, since the Selection panel may be off-screen in the stacked mobile layout.

### Keyboard (D-08)

One Tab stop. The canvas is `role="application"` (arrow keys are consumed; same precedent as the demon matrix), `tabIndex={0}`, `aria-label` per Copywriting.

| Key | At zone level | While the ring is on an edge |
|-----|---------------|-------------------------------|
| ArrowRight / ArrowDown | Next zone (zone id order, wraps) | Next zone after the edge's owner zone, ring returns to zone level |
| ArrowLeft / ArrowUp | Previous zone (wraps) | Previous zone, ring returns to zone level |
| Home / End | First / last zone | same |
| Page Down / Page Up | +10 / -10 zones, clamped `[default]` (n reaches 4000, so linear stepping alone is not usable) | same |
| Tab | Ring to this zone's **syzygy**, then its **current**, then its **gate** (edges that are muted or absent are skipped). After the last one, Tab leaves the canvas to the next page control. | Next edge, or leave the canvas after the gate |
| Shift+Tab | Leaves the canvas to the previous page control | Previous edge, or back to the zone, then leaves the canvas |
| Enter / Space | Pin the zone (same calls as a click: `onPinInfo` + `onZoneNodeClick`) | Pin the edge (`onPinInfo`) |
| `+` / `-` / `0` | Zoom in / out about the ring target / fit (same keys as the demon matrix) | same |

- Tab never traps: it exits after the last sub-stop. Escape is left alone (the app already uses it to clear selection).
- Pair-graph view: arrows visit pairs in pair-id order, Enter pins, Tab leaves the canvas (no sub-stops), matching `PairGraphProjection.tsx`.
- Keyboard focus counts as hover: moving the ring calls `onHoverInfo` for its target, blur clears it. That is what draws the focused zone's own edges when the gate layer is off, so every gate stays reachable by keyboard.
- **The ring auto-pans to stay visible:** whenever the ring target would fall outside the window (or within 24 CSS px of its edge), pan so it is inside (as the matrix's `ensureCellVisible`). A focus indicator that is off-screen is a failure.
- Key handling is paused while the Computing State is active (see below); focus stays on the canvas.

### Focus ring (non-colour cue)

- **Zone:** a solid circle outline, stroke 2 CSS px `#10ff50`, radius `max(R_px + 3, 6)` (the 2px gap + 1px half-stroke of the CSS ring, with a 6px floor so it stays visible on 1.5px dots). The visible gap between node and ring is the shape cue: it reads as an outline even with colour removed.
- **Edge:** an underlay stroke in `#10ff50`, edge width + 4 CSS px, opacity 0.9, drawn beneath the edge itself, plus the callout chip naming it. The chip text is the non-colour identification.
- **Pair pill:** a rounded-rectangle outline with the same 2px stroke and 3px gap.
- The canvas element itself sets `outline: none` (like the matrix); the painted ring is the focus indicator. Ring drawing lives on the interaction layer so a Tab or arrow press never forces a full scene redraw.
- A selected zone keeps its zone-color glow ring; the accent ring is only ever the keyboard focus. Hover is a highlight (stronger stroke, on-demand edges), not a ring.

### Announcements (`aria-live="polite"`, sr-only)

One `<div aria-live="polite" className="sr-only" data-canvas-live>` beside the canvas (matrix precedent). Wording reuses the SVG tier's own `aria-label` strings so both tiers read identically:

| Event | Announcement |
|-------|--------------|
| Ring moves to a zone | `Zone {label}, {Region}` (+ `, selected` if it is in the selection) |
| Ring moves to an edge | `Syzygy {a}::{b}` / `Current {name}: {label}` / `Gate {name}: zone {from} to zone {to}` |
| Enter on a zone | `{zone announcement}, selected` or `{zone announcement}, not selected` |
| Enter on an edge | `{edge announcement}, pinned` |
| A worker result lands | `Base {n} ready.` (via the picker status region, below) |

Non-colour cues otherwise carry over from the SVG tier: edge kinds differ by stroke pattern (syzygy dotted, current solid with arrowhead, gate dashed with arrowhead), selected nodes by thicker stroke plus outer ring, muted by absence, isolate by dimming. At fit, region identity is carried by position (the layout groups zones by region), the region captions where legible, the callout, the Regions panel text and the text view.

## Computing State (D-07)

| State | Trigger | Diagram area | Picker status slot | Screen reader |
|-------|---------|--------------|--------------------|---------------|
| Ready | result for the latest request is shown | normal | the existing summary line | silent |
| Pending | a worker request has been in flight **more than 150 ms** `[default]` | previous result stays, **opacity 0.5**, `pointer-events: none`, canvas `aria-busy="true"`, key handling paused | `Computing base {n}...` | `role="status"` text is announced politely |
| Ready after pending | result for the latest request arrives | instant swap, no cross-fade | summary line returns | `Base {n} ready.` announced once through the same region |
| Superseded | a result for an older request arrives | discarded, nothing visible | unchanged | silent |
| Failed | worker error or start failure | previous result, **undimmed** | refusal line (below) in `#f87171` | `role="status"` |

- **Why 150 ms:** results that land faster than that never flash a dim or a status (the base-switch budget is 500 ms; most 202 to 4000 builds are far quicker). Below the grace period the page behaves exactly as if the result had been synchronous.
- **Dim value:** 0.5 is deliberately different from the 0.2 isolate-dimmed look so "stale" is never confused with "isolated out". Transition `opacity 0.15s` (the app's existing hover transition), automatically collapsed under reduced motion by the global rule. No blur, no overlay, no spinner.
- **Status slot:** the `summaryLine(...)` `<span id={summaryId}>` in `BasePicker.tsx`'s collapsed control is **replaced in place** (same element, 10px / 400 / gray-400, `truncate`), so the control's width and the header never shift. The text never wraps; the full text is always in the DOM for screen readers. The base numeral shows the requested base (the debounced candidate) as it already does; the header description (`Base {n}`) and the diagram keep naming the displayed base until the swap.
- **Static by design:** the status has no animated indicator and no motion in any mode, so it needs no reduced-motion variant. The trailing `...` is literal text.
- **Scope of the dim:** the diagram only. The panels keep their last data (they re-render at the swap, as the Zones and Regions lists already do when the base changes) and the Selection panel is untouched.
- **Applies to** any worker request that outlives 150 ms: base change, layout or packer change at the Canvas tier, label-scheme change that needs recomputation. All use the one status string. Main-thread fallback must paint the status before it starts blocking work (yield one frame).
- **Failure lines** use the picker's existing inline refusal slot (the last row of the expanded control, after the stepper, slider, chips, type counts, optional packer and label-scheme controls, and the collapsed span): `#f87171`, 10px, `role="status"`, in the "problem, then `Showing base {lastValid}.`" format of Phase 4.

## Over-Limit Message (D-01, D-02)

- **Trigger:** a committed, valid base above the **shipped interactive ceiling** (4000 today). The cutoff is read from the shipped-ceiling datum in the data layer (name and file are the planner's call per CONTEXT; it is not `boundaries.canvasMaxN`, which stays `null`), passed to the component as a prop exactly as `svgRichMaxN` is passed today. It must never appear as a literal in a component or a test expectation.
- **Layout:** unchanged from Phase 4's `BigBaseSummary`: `section[aria-label="Numogram summary"]`, `w-[580px] max-w-[92vw] space-y-2 font-mono`, message paragraph (`role="status"`, 11px, `#f87171`), summary card (`border-[#334155] bg-[#0a1018]`, 2-column `Metric` grid: Zones, Warp, Torque cycles, Demons), then the `TextView`. The `aria-label`, `data-post-baseline` and structure stay so existing selectors keep working.
- **No "show anyway" control, no export button, no link** [D-02, Phase 4 D-18]. The message *names* headless export as the route; the real export surface and CLI command arrive in Phase 8, which will replace the last sentence with the concrete entry point. The `tier=` override stays diagnostic-only and invisible.
- **Copy** (Copywriting Contract has the final string): short, factual, present tense, the two numbers read from data, names the route, no apology, no exclamation, no em dash.
- **Differences from today's `bigBaseMessage`:**

| | Today (Phase 4) | Phase 6 |
|---|---|---|
| Cutoff | `svgRichMaxN` (200) | shipped ceiling (4000), a different datum |
| Zone count | stated ("has 1024 zones"), redundant with the base number | dropped |
| Meaning | "more than the interactive diagram supports live" | "above the interactive limit" |
| Route | none | "To draw it, use headless export." |
| Wording of the cap | "(over 200)" | "limit of 4000", and deliberately not "ceiling", to avoid confusion with the picker's existing "safe ceiling (2^26)" refusal for typed bases |

- **Pending before this state:** typing a base above 4000 runs the worker (summary and text view are built there, up to 2^26). The previous diagram dims under the Computing State until the summary arrives, then the message plus summary replaces it.
- **Diagnostic override honesty:** if `tier=headless` forces this view at a base that is within the limit, the message must not claim the base is over the limit. It reads the tier-override string in Copywriting.

## Decisions Made Here (confirm at planning)

1. Tab semantics for D-08: Tab steps zone, syzygy, current, gate, then leaves (no trap); arrows move between zones; Page Up/Down jump 10 `[default]`.
2. Particles, orbits and authored presets are SVG-only; Time Circuit draws statically. The Layers panel says so (`N/A`).
3. The Zones, Syzygies, Currents and Gates list panels show a note at the Canvas tier rather than 4000-row lists. Needs the user's nod if lists were expected.
4. `TEXT_VIEW_ZONE_LIMIT` is 1024, so for bases 1025 to 4000 the Text panel carries only header lines. Recommended: let the worker build the full listing and make the limit follow the shipped ceiling (data), so the non-visual fallback is complete at every Canvas base. If the limit stays, the keyboard model is the only complete non-visual route for 1025 to 4000.
5. 150 ms grace, 0.5 dim, 8px tap slop, 6px caption floor, 1.5px node floor, zoom ceiling formula (clamped to 100) are `[default]` values.
6. `tier=canvas` combined with an authored base-10 preset layout falls back to SVG for that preset (diagnostic only, not specified further).

### Checker recommendations carried into planning (non-blocking)

1. **"Ready" announcement needs a persistent carrier.** The picker's summary span has no `role`, and a `role="status"` added only at swap time is not reliably announced. Specify a persistent sr-only `role="status"` element in the picker (or reuse `data-canvas-live`) that carries `Computing base {n}...` and `Base {n} ready.`, while the visible span keeps the summary line.
2. **Copy dead ends are intended for now.** `To draw it, use headless export.` points at a route that does not exist until Phase 8 (CONTEXT D-02 locks this split), and the failure line has no retry path (same format as Phase 4). Plans should not "fix" either one.
3. **Typography exclusions.** The Canvas-tier panel note reuses the 9px `PanelUnavailable` style (a fifth DOM size) and canvas-painted labels are bold (700). Either set the new note at 10px (Body) or state the 9px and 700 exclusions as inherited from the SVG tier.
4. **12px is outside the standard 4/8/16/24 spacing set.** Move the 12px pick radius out of the Spacing table into the Interaction Contract (it is the D-09 constant), and either record 12px as a named exception for the callout offset (it matches the demon matrix tooltip's `x + 12, y + 12`) or snap that offset to 8 or 16.
5. **Edge-on-demand cost at n = 4000.** D-04 says hover or pin, but this spec also draws selection, region highlight and demon focus edges at full styling. A region highlight or select-all could mean thousands of heavy edges against the 100 ms `interactionMs` budget. Plans should add a fidelity-downgrade count threshold and a Verification Hook that measures it.
6. **Accent colour scope.** The existing `ShortcutsModal` lead-ins use `#10ff50` spans. State that the new line's lead-in is plain gray or the existing label style, so the accent does not spread beyond the reserved list.
