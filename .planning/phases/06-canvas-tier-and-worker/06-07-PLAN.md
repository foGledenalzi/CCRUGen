above it" (UI-SPEC "Error state: no worker" copy, `noWorkerMessage`); the fallback yields one frame (`requestAnimationFrame` then
`setTimeout 0`) so the computing status paints before blocking work; no watchdog timer (a long job keeps its in-flight slot; the next
request waits in the single pending slot).

```typescript
import { WORKER_PROTOCOL, isWorkerResponse, type BuildRequest, type WorkerRequest, type WorkerResponse } from './protocol'
export interface WorkerLike {
  postMessage(message: unknown, options?: { transfer?: Transferable[] }): void
  terminate(): void
  onmessage: ((e: MessageEvent) => void) | null
  onerror: ((e: Event) => void) | null
}
export interface WorkerClientOptions {
  readonly makeWorker: () => WorkerLike | null       // null or a throw = no worker
  readonly fallback: (req: WorkerRequest) => WorkerResponse
  readonly fallbackMaxBase: number                   // INTERACTIVE_MAX_N in the app
  readonly schedule: (job: () => void) => void       // the app yields one frame; tests run jobs synchronously or on demand
}
export class WorkerClient {
  constructor(options: WorkerClientOptions)
  get latest(): number
  request(req: BuildRequest, onResult: (resp: WorkerResponse) => void): number
  supersede(): void
  dispose(): void
}
/** The ONLY place a Worker is constructed: the literal form webpack 5 bundles as a same-origin chunk (verified under Next 14.2.35 export, root and basePath). */
export function createNumogramWorker(): Worker {
  return new Worker(new URL('../../../workers/numogram.worker.ts', import.meta.url))
}
```
State: `latestId`, `inFlight: { id, onResult } | null`, `pending: { msg, onResult } | null`, `worker: WorkerLike | null`, `created: boolean`, `dead: boolean`, `disposed: boolean`.
`request`: `id = ++latestId`; `msg = { protocol: WORKER_PROTOCOL, type: 'build', id, ...req }`; if disposed return id; if not created, create once (try/catch; null or throw -> dead);
if dead -> runFallback(msg, onResult); else if inFlight null -> post, inFlight = { id, onResult }; else pending = { msg, onResult }.
`onmessage`: ignore unless `isWorkerResponse(e.data)` and `inFlight !== null` and `e.data.id === inFlight.id`; take inFlight, clear it, deliver only when `e.data.id === latestId`; then if pending and `pending.msg.id === latestId` post it (else drop it).
`onerror`: dead = true; terminate once; set worker null; re-run inFlight (if its id is latest; its original msg must be kept with the in-flight record) and pending (if latest) through runFallback.
`runFallback(msg, onResult)`: `schedule(() => { if (msg.id !== latestId) return; if (msg.base > fallbackMaxBase) onResult({ protocol: WORKER_PROTOCOL, type: 'error', id: msg.id, base: msg.base, reason: 'no-worker', message: 'no background worker' }); else { const r = fallback(msg); if (r.id === latestId) onResult(r) } })`.
`supersede`: `latestId++`; pending = null. `dispose`: idempotent; terminate the worker if any; clear slots; disposed = true.
