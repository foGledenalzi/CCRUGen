<objective>
Build the pure typed-array Canvas scene in the engine (D-04, D-05): from a numogram, a zone layout (ring, ladder, spiral) or the pair
graph, and the engine's own routes, produce coordinates, edge curves, gate data, pair-graph pills and arcs, and flattened pick segments.

Purpose: the worker (06-04) builds this scene off the main thread and transfers it; the Canvas renderer (06-08, 06-10) draws and picks
from it. Both tiers then consume the same coordinate arrays and routes, so Canvas is not second-class and never re-routes. Living in
the engine keeps it pure and reusable by the Phase 8 CLI.
Output: `engine/scene/canvasScene.ts`, its barrel export and one engine test file.

Route grammar (engine/layout/routing.ts lines 19-32, 139, 190, 301): every zone-layout route is exactly `M x y` followed by ONE of
`L x y` or `Q cx cy x y` (numbers from `fmt`: `String(Math.round(v * 100) / 100)`). Pair-graph routes (pairgraph.ts) are
`M x y A r r 0 f s x y` arcs and loops (drawn later with `new Path2D(d)`; pair-graph arcs are not pickable: PairGraphProjection sets
`pointerEvents: 'none'` on them, only pills are interactive).

Syzygy trimming to copy exactly (engine/scene/svgString.ts lines 192-214): for pair q with lo/hi zones, r = layout.nodeRadius,
rLo = nodeRadii?.[lo] ?? r, rHi = nodeRadii?.[hi] ?? r, dist = hypot(x2 - x1, y2 - y1); if dist <= 2 * r draw centre to centre, else
start = lo centre + unit * rLo, end = hi centre - unit * rHi.

Numogram methods used: `g.base`, `g.zoneCount`, `g.pairCount`, `g.pair(q) -> { lo, hi }`, `g.current(q) -> { to }`.
Engine functions for tests: `createNumogram`, `resolveLayout(g, id, [], { packer })`, `pairGraphLayout(g, { packer })`,
`routeGates(g, layout)`, `routeCurrents(g, layout)`, `routePairGraph(g, pg)`.
Test idioms: engine/test/layout.routing.test.ts `endpoints(d)` regex helper (lines 12-26) and the capped mismatch collector.
Engine purity: relative imports only; no DOM types (no Path2D, no ArrayBuffer transfer lists here); typed arrays are fine.
