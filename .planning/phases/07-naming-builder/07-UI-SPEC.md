# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Read alongside:** `07-CONTEXT.md` (D-01..D-14, locked and not re-asked here), `04-UI-SPEC.md`, `05-UI-SPEC.md` and `06-UI-SPEC.md` (tokens, spacing convention, copy voice, Cyber component set, data-* hook style). Nothing in this document restyles an existing control. The identity is CCRUG; nothing here reintroduces upstream branding.

**Character of the phase:** one new surface (the Names panel) plus small edits to surfaces that already exist (the label-scheme row, the Labels panel row text in one mode, the zone node label slot on both diagram tiers, the demon name displays, the Selection demon detail, and the desktop panel stack so it follows real panel heights). Everything new reuses the existing Cyber vocabulary. Everything new in the DOM carries `data-post-baseline=""` (or sits inside a subtree that does), so `e2e/__behaviour__` and the 60 DOM goldens do not change.

**Provenance key:** `[D-nn]` = locked in 07-CONTEXT.md. `[parity]` = copied from existing code that was read for this contract. `[derived]` = forced by a locked decision, a frozen oracle or a requirement. `[default]` = this document's choice where CONTEXT left discretion; the planner may tune a `[default]` value without reopening the contract but may not drop the rule. Every `[default]` and `[derived]` that the user might care about is repeated under "Decisions Made Here".

**Revision 1 (2026-10-19), checker findings applied:** specific button labels instead of single-word CTAs and import errors with a next step (copy blocker); desktop placement rebuilt on real code constants (columns, widths, open-state boxes), the desktop stack made live from measured heights (folds todo 008), the Names desktop slot moved under the Selection panel, mobile slot moved to the top of the stack, mobile body clamp and toolbar clearance made consistent, collision jump gets an inline rename editor that always works, `ui-terminal-field` underline and row width recomputed, Cyber component prop gaps listed, radio rows wrap, label level-of-detail exception for preset layouts and both Canvas passes named, seed-only derived from the base alone, visible style and join descriptions, `Numbers` toggle wording in `sounds` mode, share-note placement, panel z-index cap, 820px boundary wording, spacing exceptions reduced.

**Revision 2 (2026-10-19), final checker pass and user decision:** the user chose to fold the **whole desktop panel-stack fix** into this phase (todo 008 is closed by it); the bottom reserve is 96px on desktop as on mobile, with an 80px minimum body, so an open Names box clears the zoom toolbar and the `shortcuts` button; field-width figures corrected for the thin scrollbar (about 206px content, 142px field) with a measure-in-the-browser check; the demon name editor stays bound to the demon it was opened on regardless of hover; the collision jump no longer pins, so Names never moves under the pointer; "accessible name contains the visible text" wording; 991 x 800 added; the unrounded-chain rounding and the `startDrag` seed trap added to the stack rule; layout-sensitive specs to re-run listed.

**Visual hierarchy:** the diagram stays the primary focal point at every base and tier. The Names panel is secondary chrome like Layers and Labels. Inside the panel the zone list is the working surface and the global controls above it are quiet: 8px eyebrows, 10px helper lines, no icon except the lock, no accent except the reserved list below.

### Component prop additions (proof of "default DOM identical")

Every new prop is optional and, when absent, emits no attribute and changes no class. The proof is the existing pattern in `tests/app/demonsOverlayRender.test.ts` (`CyberButton: markup identity (T-05-31)`), extended for `CyberButton` and mirrored in a new `tests/app/cyberControlsMarkup.test.ts` for `CyberRadio` and `CyberCheckbox`: each renders the component without the new props and asserts the markup is byte-equal to the pre-change string, then renders each new prop once and asserts exactly the one expected attribute. `dataAttrs` accepts only keys starting `data-`. These additions are why the Names panel can set `aria-expanded`, `aria-pressed`, `title`, an accessible name that contains the visible text, and the `data-names-*` hooks without wrapping every control in a new element.

## Spacing Scale

Layout-level values introduced by Phase 7 (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between the label, field and lock inside a zone row; gap between jump buttons in a collision line; gap between a field and its message |
| sm | 8px | Vertical gap between control blocks (`space-y-2`), notice padding, button gap in the import and export row |
| md | 16px | Not used |
| lg | 24px | Minimum interactive target: lock button (24x24), every `size="sm"` button (`min-h-[24px]`), every radio and checkbox wrapper (`min-h-[24px]`), the sticky list header, preview-table rows |
| xl | 32px | Zone label column width |
| 2xl / 3xl | 48 / 64px | Not used |

Exceptions (each justified; all but the last two are inherited density conventions or existing constants):
- Panel inner horizontal padding **12px** (`px-3`, the existing panel convention). Panel body bottom padding 10px (`pb-2.5`, existing).
- **Zone row height 28px** (`h-7`): the 24px lock plus 2px hairlines above and below; the one value in this phase that is a multiple of 4 but not on the 4/8/16/24/32 set.
- Hairline 2px (`py-0.5`) and chip padding 6px (`px-1.5`), inherited from Phase 4's 2px-based scale.
- **Stack gap 18px on desktop** (`DESKTOP_PANEL_GAP`, existing constant) and **6px on mobile** (`gap: 6` in `usePanelGroupLayout`, existing); panel header 34px (existing default height).
- **Bottom reserve 96px on mobile and on desktop** (matches Phase 6's `100vh - 96px`): the zoom toolbar (`ViewControls`, fixed `bottom-12 right-3`) spans about `vw - 169` to `vw - 12` in x and about `vh - 76` to `vh - 48` in y, and the `shortcuts` button (fixed `bottom-3 right-3`) sits below it; both are z 74, above every panel, so an open panel must end above `vh - 96` (about 20px of clearance).
- **548px** (Names minimum x on desktop) is `536 + 12`: the Text panel's open right edge (`216 + INFO_PANEL_WIDTH 320`) plus a 12px gap. It is derived from code constants, not an arbitrary value.
- Matrix tooltip offset 12px (existing).

## Names Panel Contract

### Component, size, mount [D-01, D-02]

| Property | Rule |
|----------|------|
| Component | `CyberPanel` with `id="names"`, `title="Names"`, `postBaseline`, `collapseDirection="vertical"`, `onHeightChange={onPanelHeight}`, `onActivate={activatePanel}`, `onDragStart={startDrag}`, `draggable={!isMobile}`. `names` is added to `PANEL_GROUP_DEFAULT_HEIGHTS` (34), to `usePanelDrag`'s position and z-index maps (initial z-index 49, above `text` 48) and **first** in the mobile `PANEL_GROUP_ORDER`. |
| Width | **240px on desktop** (a new constant; the other desktop panels are 180px, Text and Selection 320px, and a 16-character sound needs the room). At **820px and below** (`isMobile`, `viewport.w <= 820`): `mobilePanelWidth`, which is `max(170, min(240, vw - 16))`, the same as every non-Selection panel. |
| Default state | **Collapsed** on first load at every width, like the Text panel. It opens automatically once when a link puts the panel into the unsaved-preview state (so the D-13 notice is seen). Open/closed is not persisted and not in the URL. |
| Mount | At **every** tier (SVG, Canvas, headless) and every base: the demon browser shows names everywhere, so naming state must always exist. The panel's state depends on the **base** only (see States); a diagnostic `?tier=` override never changes it. |
| Height reporting | Through `CyberPanel` `onHeightChange` (the real measured height, `ResizeObserver`). The panel must keep reporting when its content grows (notice appears, list message appears, collision list expands, inline editor opens), because both stacks position other panels from it. |
| Scrolling | The panel body has **one** scroll container, `data-names-scroll`, containing the controls and the virtualized list. It sets `overflow-x: hidden` explicitly (a bare `overflow-y: auto` would otherwise compute `overflow-x: auto` and show a horizontal bar), `overscroll-behavior: contain`, `touch-action: pan-y`. | Body height | `bodyMax = clamp(80, vh - (panelY + 34) - 96, 560)`: **the same 96px bottom reserve at every width** (on desktop the zoom toolbar and the `shortcuts` button also sit at the bottom right at z 74, so an open Names box ending at `vh - 16` would run under them) and a stated **minimum body of 80px** (the sticky header plus two rows). The body is never forced above the minimum: it shrinks to 80px and scrolls inside its single scroller. On mobile `panelY` is always 64 (Names is first), so the 80px minimum binds only when `vh < 274` (out of scope). On desktop it is recomputed from the panel's current y (see the stack rule for worked numbers and the worst case). |
| Panel stacking | z-index uses the existing `panelZ` mechanism plus the cap in Desktop Panel Stack Rule, which is what makes "never above the toolbar, overlay or dropdown" true. |

### Desktop Panel Stack Rule (above 820px) [D-01, closes todo 008]

CONTEXT D-01 says the panel "must report its real height so the stack adapts (see todo 008)". Today the desktop stack is computed **once** (`desktopPanelLayoutInitRef` in `NumogramClient.tsx`, about lines 1220 to 1249) and keeps its base-10-era heights after a base change, which is the cause of todo 008 (measured: after typing base 28 the Currents panel sits at y 227 over the bottom edge, y 250, of the Regions panel). This phase makes the stack follow real heights, and Names depends on it. Scope fold **confirmed by the user on 2026-10-19** ("Fix the whole desktop stack now"): todo 008's acceptance criteria are met by this rule (see Verification Hooks) and the todo is closed by this phase.

| R | `regions`, `currents`, `gates` | 216 | 180 (x 216 to 396) | |

**Slot rule (the contract, testable):**

| Item | Rule |
|------|------|
| Inputs | The viewport, each panel's **measured height** (the unrounded `getBoundingClientRect().height` that `CyberPanel` already reports through `onHeightChange`, `CyberPanel.tsx` line 88), and each panel's `moved` flag. |
| Slots | The first panel of a column is at y = 64. Every next panel is at `y_prev + height_prev + 18`. Columns and order are exactly as in the table above. A panel is never skipped, so a collapsed panel contributes its 34px header and an open one its full height. The chain is accumulated on the **unrounded** heights and `Math.round` is applied to each resulting y at the end, exactly as the current effect does, so positions are identical to today's (no rounding accumulates). |
| Follow | A panel that the user has **not moved** is placed at its slot and re-placed whenever any panel above it in its column changes height by 1px or more (open or collapse, base change, selection growth, a notice or message appearing, the Names list growing), and when the viewport resizes. Collapsing a panel therefore pulls the panels below it in its column up, as the mobile stack does (today a collapsed desktop panel leaves a hole). The stack is **derived** from those inputs on each change, not stored: `usePanelDrag` keeps stored positions only for moved panels. |
| Moved | A panel is `moved` after the user drags its header (a header mouse-down followed by a mouse move). A moved panel keeps its dragged x and y until reload and ignores the stack. **Its slot stays reserved** (the panels below it do not jump up), which equals today's behaviour. |
| Drag seed (trap) | `startDrag` (`app/hooks/usePanelDrag.ts` lines 78 to 90) seeds the drag from the **stored** `positions`. With a derived stack the stored value of an unmoved panel is not where it is displayed, so a naive drag would make the panel jump on the first mouse move. `startDrag` must seed from the panel's **displayed** (derived) x and y, and on the first move store `displayed + mouse delta` and set `moved`. |
| Initial identity | The first application waits for the same five panels as today (`layers`, `labels`, `zones`, `regions`, `currents`) to have reported, and uses the same formula as the current one-shot effect (the **unrounded** chain with `Math.round` applied at the end). At base 10 initial load every existing panel's x, y and width therefore equal what the current build produces; the checkable form (font-independent, since the behaviour baseline records no layout metric) is: first tops 64, lefts 12 and 216, widths 180 and 320, and each other top equal to the previous top plus the previous measured height plus 18, within 1px. |
| Past `vh - 50` | A slot is **never skipped, wrapped or squeezed** (that is how overlap is created). A panel whose slot top falls below `vh - 50` is simply below the fold, exactly as Syzygies, Gates and Text already are at small heights, and is reached by collapsing the panels above it in its column. Names is placed so this does not happen at the test viewports (below). |
| Names body room | `bodyMax = clamp(80, vh - (y + 34) - 96, 560)` with `y` from the stack. The 96px reserve keeps an open Names box above the zoom toolbar (top edge about `vh - 76`) and the `shortcuts` button, both z 74. With nothing selected Selection is about 300px tall, Names y is about 382 and `bodyMax` is `vh - 512`: 256 at 768, 288 at 800, 388 at 900 (the box then ends at `vh - 96`). Worst case (Selection at its 52vh cap, about `64 + 0.52 vh` tall; measure it, do not assume it): `bodyMax = 0.48 vh - 276`, about 93 at 768, so the **80px minimum** is honoured and the box still ends at `vh - 96` for `vh >= 742`. A 160px floor cannot hold with a 96px reserve (it would need `vh >= 908` in that worst case), so the floor is lowered to 80. Below 742 in that worst case the body stays at 80px and the box may extend into the reserve band; the toolbar and `shortcuts` button stay above it (z 74) and clickable, and clearing the selection restores the room. |
| Open action | Opening Names never moves another panel and never moves Names itself (the stack gives it room below Selection); only its own height grows. |

**Why this slot** (M1, M4): Names cannot go in R or L (R's last panel sits near y 650 at base 10, so an open Names would run past the viewport, and R contains the 320px Text panel) and a free third column starting at y 64 would sit on top of the planetary controls (orbit, today/reset/orbits and the date input, fixed in the top bar, centred on `vw / 2`, starting near y 62), which an x range of 408 to 648 covers for windows of roughly 992 to 1450px. The S column puts Names at `Selection bottom + 18` (y at least about 250 at any height), which is below those controls and below the top bar for every width, to the right of the Text panel's open box (x at least 548), and with room for an open body. It also keeps working at 821 to 991px (Names x 548 to 788 at 821px, which stays inside the window).

### Mobile stack (820px and below)

`names` is **first** in `PANEL_GROUP_ORDER` (the order becomes `names, layers, labels, zones, regions, syz, currents, gates, text, info`), positioned by the existing `usePanelGroupLayout` from real measured heights with `baseY 64`, `gap 6`, `x = 8`. Reasons (M2): the Selection panel is **not** collapsible (`showToggle={false}`, no `collapseDirection`) and its body is up to 52vh (about 410px tall when pinned at 375 x 667, about 270px with nothing selected), seven other panels start open, and only Text starts collapsed; any slot after Selection is below the fold even with every other panel collapsed (stack of eight 40px rows ends near y 384, Selection to about y 795). First puts the collapsed header at y 64 with no precondition, and an open Names body at `64 + 34 + bodyMax`, where `bodyMax = min(560, vh - 98 - 96)` is 473 at 667px, so the open panel ends at y 571. Cost: every other mobile panel moves down by 40px (34 header plus the 6px gap) and, while Names is open, by its full height; the stack never overlaps because it uses real heights. The behaviour baseline records text, flags and open state, not positions (`e2e/behaviour-collect.ts`), so `npm run test:swap` is unaffected; `e2e/canvas-interaction.spec.ts` at 375 x 667 and 768 x 1024 must be re-run because it touches the mobile layout (Decision 3).

### Replace-all actions and their inline Undo [D-09, D-10, D-13]

`Keep this naming`, switching `Source`, a changed seed, `Reroll unlocked sounds`, a changed style, `Import names`, and `Use its seed here` each replace some or all of the working naming. None needs a confirmation dialog (project no-modal precedent from Phase 4). Each ends with a one-line result status in block 10's status slot and an inline `Undo this change` button (`CyberButton size="sm"`, on its own line) that calls the app's own `onUndo`; the status and button stay until the next naming action, a base change, or the panel collapses. Undo restores the previous in-memory naming and autosave then rewrites the slot, so nothing is lost silently.

### What changes on the diagram `[default]`

The mode swaps **only the zone node label slot** (the bold text at the node centre that the toggle above shows or hides). Every other label keeps numerals: gate meeting labels, syzygy and current text, pair-graph pills, the Zones, Syzygies, Currents and Gates panels, the A::B column, the Text view and every `{label}` placeholder in callouts. `zoneLabel(z)` therefore resolves to the digits label in `sounds` mode; a separate sound lookup feeds the node slot. This honours D-03's deferral (no sound in Zones panel rows) and keeps net-span identity compact and numeric.

- **Accessible name:** in `sounds` mode a zone's name becomes `Zone {digits}, sound {sound}, {Region}` (with `, selected` where it applies) on the SVG node `aria-label`, the Canvas callout chip and the Canvas announcements, so the visible text is always inside the accessible name. The sound is always the full, untruncated one. Outside `sounds` mode every string is byte-identical to today.
- **Pair graph and planetary layouts** keep numerals (pills hold two names; planetary spheres vary in size). The note above says so.
- **Seed-only bases** (`base > INTERACTIVE_MAX_N`): no per-zone sounds exist, so `sounds` mode draws digits there even if a diagnostic `tier=` override draws a diagram.

### Fitting long sounds `[default]`

One pure function, shared by both tiers and both Canvas passes so they agree, takes the sound, the on-screen node radius `R_px`, the layout `labelSize` and the px-per-world-unit scale, and returns the text and the font size. `R_px` is computed exactly as the existing level of detail does (`target.nodeRadius * (580 / svgWidth) * zoom` on the SVG tier; `scene` geometry on Canvas).

**Level of detail is unchanged, with one existing exception stated here (M9).** Nothing is drawn below `labelsShown(R_px)` (`LABEL_MIN_RADIUS_PX`, 7, read by property access through `app/lib/tierBounds.ts`; never the whole tier-table JSON, never a literal) **except on base-10 preset layouts**: `NumogramClient.tsx` sets `labelsOn = target.preset || labelsShown(...)`, so the original, labyrinth, ladder and planetary presets draw labels at any `R_px` (at the minimum zoom of 0.3 the base-10 `R_px` is about 4.6). On those layouts the fit rule still applies at whatever `R_px` results, and the case `m < 2` below can occur.

| Step | Rule |
|------|------|
| Width estimate | 0.62 em per grapheme (conservative for the generic monospace family); 1.0 em for East Asian wide and fullwidth graphemes. Graphemes counted with `Intl.Segmenter`, never UTF-16 units. |
| Budget | `W = 1.8 x R_px` (90% of the node diameter). |
| Fits at full size | If `estimate(F_full) <= W`, draw at the layout's normal `labelSize` (bold, same colors and opacities as numerals). |
| Shrink | Otherwise draw at `F_fit = W / (0.62 x L)`, but never below **6 CSS px** (the project's smallest legible text; Phase 6's region-caption floor). |
| Truncate | If `F_fit < 6px`, draw at 6px and keep `m = floor(W / (0.62 x 6))` graphemes with the last one replaced by `…` (U+2026). If `m < 2` keep only the first grapheme without an ellipsis (it occurs only on preset layouts at very low zoom, where `R_px < 3.4`). Never cut inside a grapheme. |
| Worked example (base 10, original layout, 580 px column, R=21, label 17, scale 0.725) | `R_px` 15.2, full size 12.3px, `W` 27.4px. `eiaoung` (7) shrinks to about **6.3px**; `gl`, `dt`, `zx`, `skr`, `ktt`, `tch`, `pb`, `mnm`, `tn` stay at 12.3px. A 16-character sound becomes 6px, 7 graphemes, `abcdef…`. At `R_px` 7 (the Canvas threshold) any sound keeps 3 graphemes (`ei…`). Zooming raises `R_px` and restores full text. |

**SVG tier:** the `<text>` gets its fitted size and text in world units; **only in `sounds` mode** it also carries `data-sound-label="{full sound}"` and, when cut, `data-truncated="true"`.

**Canvas tier paints zone labels in two passes and both must use the fit:** the static node pass (`lib/canvas/draw.ts`, the loop that sets `ctx.font = bold ${scene.labelSize * geo.s}px monospace` near line 880) and the highlight overlay pass (the same font line near line 1555). Today each sets one font before its loop. In `sounds` mode the font is set **per label** (or per distinct fitted size, grouping allowed) inside the loop. The overlay pass must produce exactly the same text and size as the static pass for the same node, otherwise a highlighted label would ghost over the static one. Both honour the label toggle and `geo.lod`. The digits path in both tiers and both passes must remain byte-identical.

### Fallback label

A zone with no sound yet (the naming is `pending`, or the base is seed-only) draws its normal **digits label**, in the normal numeral style, never fitted, never italic, never a placeholder glyph. This is the same "never a wrong label" fallback the custom alphabets use. An empty sound cannot be committed (D-07), so there is no other "missing" case.

## Decisions Made Here (confirm at planning)

1. **Desktop slot `[default]`: the Selection column, directly under Selection** (x = `max(selectionX, 548)`, y = Selection bottom + 18), collapsed by default, auto-opening once for a link preview. Chosen because a third column at y 64 would cover the planetary controls for windows of about 992 to 1450px, the right column ends near y 650 and holds the 320px Text panel, and under Selection the panel has room (with the 96px bottom reserve the open body is about 256 at 768 with nothing selected; with Selection at its 52vh cap the body shrinks to its 80px minimum and the box still ends above the toolbar from vh 742). Alternative if the user dislikes Names moving down when Selection grows: a fixed slot at the right viewport edge, which would then need its own overlap rule.
2. **Desktop stack made live; user-confirmed 2026-10-19 (no longer a default).** The user answered the scope question with "Fix the whole desktop stack now". The one-shot layout effect becomes a stack derived from measured heights (rule above): **collapsing a panel pulls the panels below it in its column up, as on mobile** (today a collapsed desktop panel leaves a hole), and the stack re-measures on every content change, including a base change; a panel the user has dragged stays where dragged and its slot stays reserved; at base 10 initial load every existing panel is placed exactly as today (unrounded chain, `Math.round` at the end). **Todo 008 is closed by this phase** and the fix is required by D-01's "stack adapts". Plan impact: `e2e/layers-zoom.spec.ts` (collapse and expand of Zones; reaching the Text header at 1280 x 1300), `e2e/canvas-tier.spec.ts` (reaching the Text header at 1280 x 1300), `e2e/row-click-regression.spec.ts` (real mouse clicks on rows at base 10) and `e2e/region-legend.spec.ts` (base switch) rely on today's stack and must be re-run, plus the new todo 008 regression assertion.
3. **Mobile slot `[default]`: Names first** (y 64). The earlier "last" order left Names below the fold even with every collapsible panel closed, because Selection is not collapsible and is up to 52vh tall. Cost: while Names is collapsed every other mobile panel sits 40px lower; **while it is open the entire stack is pushed down by Names' open height (34 + 473 = 507px at 667, plus the 6px gap)**, computed from real heights so nothing overlaps. The behaviour baseline records no positions, so `npm run test:swap` is unaffected; re-run the layout-sensitive specs listed in Frozen Constraints (`e2e/canvas-interaction.spec.ts` at 375 x 667 and 768 x 1024 for coordinate-based taps, and the others).
4. **Panel z-index cap `[default]`.** A small fix in `usePanelDrag` (re-rank onto 40 to 49 when the counter would pass 69) so the "never covers the toolbar, overlay or dropdown" guarantee is true; without it the existing counter can raise a panel above all three.
5. **Collision jump opens an inline rename editor and does not pin `[default]`.** The editor opens in the collision line (focus in its field) because the Selection panel cannot always show a pinned demon and is far down the phone stack. The jump does not pin: a pin changes Selection's height, and Names follows Selection in the stack, so a pin would move Names under the pointer. The editor is one component with three mounts (Selection, overlay aside, collision line), told apart by `data-demon-name-context`, and it stays bound to the demon it was opened on regardless of hover. Alternative if the user wants the diagram highlight too: pin as well and freeze Names' y until the editor closes (which can overlap if Selection grows).
6. **Share note in three places `[default]`.** Panel line, collapsed header tag `edits not in links`, and the Share button's `title` plus an announcement; the Share button's behaviour and look are unchanged.
7. **Base 10 default is the CCRU preset `[derived]`.** Reconciles D-10 ("fresh seeded") with DEM-05, D-14 and the frozen baseline. A slot is written only after the first user edit `[default]`, so D-13's notice never fires over an untouched default.
8. **Editing a sound auto-locks its zone `[default]`.** Otherwise Reroll or a new seed would silently discard typed work. Bulk paste locks too.
9. **Commit model `[default]`.** Sounds commit on Enter or blur (one history entry each); invalid drafts stay visible with one list-level message line (fixed 28px virtual rows cannot host per-row messages); all-or-nothing paste and import; unknown import keys listed but non-blocking; trimmed ends allowed, interior whitespace refused.
10. **`sounds` mode touches only the zone node label slot `[default]`.** Numerals stay everywhere else (also keeps D-03's deferral and compact A::B identity); the accessible name gains the full sound; the Labels panel row reads `Sounds` only in this mode; pair graph and planetary keep numerals; seed-only bases draw digits. Fit rule: 0.62 em per grapheme (1.0 em for wide scripts), 90% of the node diameter, 6px floor, ellipsis truncation, shared by both tiers and both Canvas passes; base-10 preset layouts keep their existing always-on labels.
11. **Override rules `[default]`.** Same character rule as sounds, 1 to 32 characters (CONTEXT only specifies sounds). Equal-to-derived saves as a reset. Renaming is not offered above `INTERACTIVE_MAX_N` because it could be neither saved nor exported (D-11). Canonical CCRU names carry no override marker; only user overrides do (`*` plus hidden text). Reset label becomes `Reset to CCRU name` for canonical demons.
12. **Preview is fully read-only `[default]`.** Otherwise an edit during preview would either save over the slot or be lost.
13. **14px field text `[default]`, with the iOS trade-off.** The Phase 4 Input role; a 16px field would hold only 14 characters in the 142px field, while 14px holds 16 (about 134px). iOS Safari zooms into fields below 16px on focus, as it already does for the demon search and base picker fields.
14. **Quiet list fields `[default]`.** Two new CSS modifier classes (`--quiet`, `--invalid`) because the standard `ui-terminal-field` has an always-on green underline and 14px right padding that would put 4,000 permanent green rules in the list and cost 14px of the field.
15. **Collision report shape `[default]`.** Counts distinct repeated names and the demons involved; list capped at 20 with `Show more names` (no nested scroller); collisions are neutral gray-100, not red; check limit read from data and defaults to the editing ceiling.
16. **Panel extras beyond D-02 `[default]`.** `Go to zone` field (a 4,000-row list is unusable without one), a pinned-zone scroll link, the preview table (3 rows, truncating cells), the summary and share-note lines, and the reroll button (`crypto.getRandomValues` in UI code; the engine generator stays deterministic). Drop any of these without reopening the contract if the panel proves too tall.
17. **Specific button labels.** `Export names`, `Import names`, `Reroll unlocked sounds`, `Rename demon`, `Save name`, `Cancel rename`, `Reset to generated name`, `Undo this change`, `Show repeated names`, `Show more names`; the seed field and the reroll button therefore sit on separate rows.
18. **Component prop additions.** `CyberButton`, `CyberRadio`, `CyberCheckbox` gain optional props with a markup-identity test each, instead of wrapping controls in extra elements.
19. **One scroller.** The panel's controls and list share one scroll container (no nested scrollbars), at the price of the controls scrolling away while editing far down the list.
20. **No drag and drop, no name search, no sort by name.** Searching demons by name would need a name index at 221,445 demons; the NAME column stays non-sortable.
21. **No autosave above the ceiling `[derived]`.** D-11 lists autosave under full editing, so seed-only bases are saved only by the page link (the URL keeps the seed and style) and by export.
22. **Matrix tooltip names are cut at 32 graphemes.** The editor and Selection detail always show the full name.
23. **Desktop bottom reserve 96px and an 80px minimum body `[default]`.** The zoom toolbar and `shortcuts` button are fixed at the bottom right at z 74, above the panels, so an open Names box ending at `vh - 16` ran under them (worked example at 1280 x 800: Names y 382 to 784 against the toolbar at x 1111 to 1268, y about 724 to 752). Reserve 96px as on mobile; the old 160px floor cannot hold with it, so the floor is 80px (sticky header plus two rows) and the body scrolls inside its single scroller.
