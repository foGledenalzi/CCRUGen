<objective>
Extend the single URL codec with the naming link and the `sounds` label mode, and keep the worker guard in step (07-RESEARCH Pattern 7,
Pitfall 5; 07-PATTERNS alert 12; orchestrator decisions 7, 8 and 10).

Purpose: NAM-03 ("the URL carries only a preset or seed") and D-03 (`sounds` joins the label scheme and its URL param, on the Canvas tier too).
Output: `app/lib/namesLink.ts`, edits to shareParams, labelScheme and the worker protocol, the ShareState literal in NumogramClient, and tests.
The URL carries no `names` value until plan 07-18 connects the naming session: here `currentShareState` passes `names: null`, which the
codec omits, so every existing URL is unchanged.

[default] decisions recorded here:
- A link without `names=` expresses no naming (the visitor's saved slot or the base default is shown); the default naming of a base is
  written as no param (canonical form computed by the session in 07-13).
- Companions (nstyle, njoin, nsmooth) are read only together with `names=seed:`; `names=ccru` ignores them.
- `names=seed:` means `names-gen@1` forever; a future generator needs a new prefix (orchestrator decision 8).
- Toggling `sounds` at a Canvas base triggers one worker rebuild (resultKey includes the label key); normalising it away is unsafe (research Pattern 7).
</objective>
