### Licensing and attribution (FND-05)
- **D-01:** This is an **own project that credits upstream**. A `NOTICE` file names `lumpenspace/ccru` as the origin of the upstream-derived files, which carry **no stated license** (upstream has no LICENSE and no `license` field). Requesting a permissive license from lumpenspace is a user action to run in parallel; do not send anything on the user's behalf.
- **D-02:** New original code (`engine/`, layout, naming, export, tests, scripts written in this project) is **MIT**. Copyright holder line: use the repo's git author name, now **`foGledenalzi`** (supersedes the earlier `csysp` default), unless the user says otherwise (open item, see Claude's Discretion).
- **D-03:** The CCRU-derived base-10 lore (`app/data/zones.ts`, `gates.ts`, `currents.ts`, `syzygies.ts`, `demons.ts`: zone/gate descriptions, names) is **third-party lore**. Evidence: gate names and phrases ("Gate of Submergence", "Gate of Charon", "Lo-Way", "Ulterior Vortex") appear in the CCRU book text; zone descriptions read as close paraphrase. It is **excluded from the MIT license and listed in NOTICE as CCRU-derived**. The text stays **unchanged** so the oracle stays byte-identical. In Phase 1 it is only marked (NOTICE + header comments); the physical move into a single clearly-marked base-10 lore file happens in Phase 2 (MIG-01, "joined with lore by id").
- **D-04:** A guard fails if anything under `reference/` is tracked (`git ls-files reference` must be empty); `reference/` content never enters tracked files beyond citations.

### Base-10 oracle (FND-02)
- **D-13:** **Numeric oracle:** `base10.golden.json` generated from the untouched `app/data/*` (pairs, currents normalized to pair + destination, gates k -> to with T(k), demon net-spans + kinds, regions, `TC_*`), with named regression tests for Gt-15 (5->6) and Gt-03 (2->3). Planetary layout is checked numerically only (its constants).
- **D-14:** **DOM oracle:** 3 non-planetary layouts (original, labyrinth, ladder) x about 5 static states each (default; each layer alone; Plex/Warp/Torque region highlight; a selected zone; time-circuit flag). Date, orbits and particles pinned; `TZ=UTC`; wait for the layout tween to settle. **Planetary is excluded from the DOM oracle.** No interaction traces in Phase 1.
- **D-15:** **Comparison is visual-DOM:** compare geometry, paint and text only (paths, coordinates, fills, strokes, transforms, text content) and **ignore `aria-*`, `role`, `tabindex`, `data-*`**, so Phase 4's accessibility additions never trip it while any visual change still does. The pre-refactor baseline is never overwritten; an intentional visual change adds a new dated golden set with a written reason. Never `-u` to make a test pass.
- **D-16:** Playwright uses its **pinned Chromium** (about 150 MB one-time download into the user's cache), Chromium only. The download must go through the normal permission prompt at execution time. Goldens are captured from the **untouched** viewer against `next dev` before any static-export decoupling or any edit to `NumogramClient.tsx`.
- **D-17:** **Page-weight baseline and budget** (user asked for this because of bloat concerns at high bases such as base 666): record the static export's JS/CSS/HTML sizes per route and the DOM node count per golden state, and add a budget check that fails on growth beyond a tolerance unless updated with a written reason. High-base fixtures are **never committed as full dumps**, only compact numeric digests (counts, hashes). Tolerance values are the planner's choice.
