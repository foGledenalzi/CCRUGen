## Summary

Phase 1 is smaller and safer than the roadmap feared. Everything below was run in a throwaway copy of the repo (`scratchpad/phase1-lab`, npm install of the exact pins: 506 packages, 26 s). The empirical unknowns resolve as follows: root `target: ES2022` with `noEmit` produces no diagnostics on the current repo (it also passes at `es5` today; ES2022 only matters for new engine code, where `for..of` over `Set`/`Map`, BigInt literals and `#private` fields fail at es5). With `output: 'export'` and `trailingSlash: true`, Next 14.2.35 fails the export on exactly two paths (`/` for `searchParams`, `/numogram` for `generateMetadata({searchParams})`); sitemap, robots, the unconditional `redirect()` in `gematria/saved`, the POST-only share route and the `@vercel/*` imports did not fail the build. After the CONTEXT decisions the whole site builds to a 6-page static `out/` in about 19 s. The stale `fetch('/api/share-image')` calls inside `NumogramClient.tsx` do not break the build but would issue 404 requests at runtime; removing them requires deleting three dead callbacks or `next build` fails on `no-unused-vars` (lab-verified).

Vitest 5.0.2 + Vite 8.3.1 run on Windows Node 22.16 without falling back to Vite 7. Two Windows facts change the TZ plan: a runtime `process.env.TZ = ...` assignment works (including IANA names), but a process-start `TZ=Asia/Tokyo` environment variable is silently ignored by Node on this machine (only `TZ=UTC` took effect under `cross-env`). So the TZ pin must be an assignment in the config, driven by a project-owned variable (`CCRUG_TZ`) so "two different TZ values" can be exercised on Windows, plus a canary test. The ESLint boundary is real but needs `no-restricted-syntax` AST selectors for "relative imports only" (the `regex` option of `no-restricted-imports` does not exist in ESLint 8.57.1) plus `import/no-restricted-paths` for `../../app`, and `tsc` alone cannot stop `import 'react'` (types resolve from `node_modules`). `git add --renormalize` after adding `.gitattributes` is a no-op (index already LF for all 194 tracked text files); 25 of the 58 tracked `dist/` files differ from what `prepare` regenerates, which confirms untracking.

The Playwright capture flow was first designed without a browser and has since been **executed and verified** (Chromium 153 installed with the user's approval; see "Playwright Capture Verification"): 30 DOM goldens captured from the untouched dev viewer are byte-identical across repeated runs, two timezones, and the post-change static export. The layout tween does **not** run for URL-loaded state (`switchLayout()` is only called from layout buttons and history apply), so the settle signal for static states is "expected viewBox height + React hydrated + 300 ms of unchanged normalized DOM", not a 600 ms tween wait or an intro-layer wait.

**Primary recommendation:** Sequence the phase as (0) hygiene and tooling that does not touch the render path, (1) capture numeric and DOM oracles from the untouched viewer against `next dev` with the original `next.config.js`, (2) apply the exact change list and switch Playwright to `serve out`, proving the goldens still match, (3) record the page-weight baseline, land `verify` and CI, and only then do the user-approved git mutations (untrack, remote rename).

## Architectural Responsibility Map

| Capability | Primary Tier | Secondary Tier | Rationale |
|------------|-------------|----------------|-----------|
| Static site emission (`output: 'export'`) | Build tooling (Next CLI) | CDN / Static host | No server exists at runtime; the artifact is `out/` |

| Page-weight budget | Build-artifact script (Node) | CI | Reads `out/` and golden files; no browser |
| Engine purity | Compiler (`tsc -p engine`) + Linter (ESLint) | CI (`typecheck`) | tsc blocks DOM/Node globals and unresolved modules; ESLint blocks bare specifiers and cross-tree imports |
| Licensing/attribution/reference guard | Repo files (LICENSE, NOTICE) + guard script | CI | Policy encoded as files plus a git-state check |

### Pattern 1: Client redirect that survives `output: 'export'`
**What:** server component renders a client component whose effect calls `location.replace(base + '/numogram/' + search + hash)`.
**When:** `/` only. `useSearchParams` is banned (needs Suspense in a static build).
**Example:** see Code Examples. Lab-verified: root build emits `location.replace("".concat(i,"/numogram/").concat(window.location.search))`; with `NEXT_PUBLIC_BASE_PATH=/ccrug` the constant `"/ccrug"` is inlined.

### Pattern 2: Frozen-baseline goldens with an immutability manifest
**What:** goldens live in `e2e/__golden__/`; `MANIFEST.json` stores `{set, date, reason, files: {name: sha256}}`. `check:repo` fails if any manifest file is missing or its hash changed; new intentional sets go in a new directory (`e2e/__golden__/2026-xx-xx-<reason>/`) with their own manifest entry. Playwright runs with `updateSnapshots: 'missing'` only during the one capture run (verified: it writes the golden AND fails the writing test, so that run exits 1 by design; the follow-up `'none'` run must exit 0) and `'none'` otherwise; CI ends with `git diff --exit-code -- e2e/__golden__ engine/test/fixtures`.

### Pattern 3: Environment pin as data, not shell
**What:** `vitest.config.mts` assigns `process.env.TZ = process.env.CCRUG_TZ ?? 'UTC'`; npm scripts set `CCRUG_TZ` with `cross-env`; a canary asserts the expected offset for that value; Playwright uses `timezoneId` per project.

### Anti-Patterns to Avoid
- **Setting `output: 'export'` before the golden capture:** `next dev` errors on `searchParams` pages under export (from Next docs, `[ASSUMED]` not run); it also violates D-16 ordering.
- **`toMatchSnapshot` of PNGs or `vitest -u`:** OS-dependent / self-healing.
- **Relying on `TZ=Zone/Name` at process start on Windows:** ignored by Node here.
- **Trusting `tsc -p engine` for "no bare imports":** `import 'react'` type-checks fine.
- **Regenerating `tsconfig.tsbuildinfo`-dependent results without `--incremental false`.**

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Deterministic ZIP | shelling out to `zip`, adm-zip, archiver | `fflate.zipSync` with fixed local-component `mtime` and sorted entries | Verified byte-identical across three TZ |
| Cross-platform env in scripts | `VAR=x cmd` | `cross-env` | Windows cmd; also avoids Git Bash path mangling of `/ccrug` |
| Static preview server | `next start` | `serve out` | `next start` is not for `output: 'export'` |
| HTML/SVG parsing for goldens | regex over raw HTML in the page | DOM `cloneNode` + `removeAttribute` inside `page.evaluate`, then Node-side newline formatting | Immune to attribute-value edge cases |
| Import boundary | custom grep script | ESLint `no-restricted-syntax` + `import/no-restricted-paths` + `tsc -p engine` | Verified to catch every negative fixture between them |
| License text | hand-edited MIT | canonical SPDX MIT text | GitHub license detection needs an unmodified LICENSE |

**Key insight:** every custom piece in this phase is glue (a 60-line reader, a 40-line guard); the correctness-bearing parts (type-check, lint, snapshot compare, zip) are library calls.

## Common Pitfalls

### Pitfall 1: `output: 'export'` breaks the golden capture, or NumogramClient is edited first
**What goes wrong:** the oracle is captured from an already-decoupled viewer, or `next dev` refuses `/numogram?...` under export.
**Why:** `generateMetadata({searchParams})` and `/` `searchParams` are request-time reads.
**Avoid:** Wave 1 runs with the original `next.config.js`; `output: 'export'` lands in Wave 2 with the page rewrites. **Warning sign:** any diff touching `app/NumogramClient.tsx` or `next.config.js` before the golden MANIFEST exists.

### Pitfall 2: Windows TZ pin that silently does nothing
**What goes wrong:** `TZ=America/New_York vitest run` still runs in the system zone, so "two TZ values" proves nothing.
**Evidence:** `TZ=Asia/Tokyo node -e ...` reported the system offset (420); assignment inside the process gave 0 (UTC) and 300 (New_York). `cross-env TZ=UTC` did work under Vitest.
**Avoid:** assign in the config from `CCRUG_TZ`; canary keyed on the same variable; Playwright `timezoneId` per project.

### Pitfall 3: Git Bash rewrites `/ccrug` in env values
**What:** `NEXT_PUBLIC_BASE_PATH=/ccrug npx next build` in Git Bash failed with `Specified basePath has to start with a /, found "C:/Program Files/Git/ccrug"`.
**Avoid:** set it through `cross-env` inside an npm script (npm runs scripts through cmd on Windows), or `MSYS_NO_PATHCONV=1`; validate the value in `next.config.js` and throw a clear message.

### Pitfall 4: Plain `<img src="/numogram-logo.svg">` is not basePath-aware
**Evidence:** the basePath build prefixed the CSS/JS/icon URLs but left both `src="/numogram-logo.svg"` (NumogramClient line 1621 and the `icon=` prop at line 1738) unprefixed.
**Avoid:** `withBasePath()` helper (Wave 2 edit, after the oracle; SVG markup is unaffected).

### Pitfall 5: Removing the share flow fails lint, not tsc
**What:** deleting only the two `fetch('/api/share-image')` blocks leaves `focusZones` unused (`@typescript-eslint/no-unused-vars` is an error inside `next build`), plus a hooks warning.
**Avoid:** delete `getShareFocusZones`, `captureShareDataUrl`, the `focusZones` line, and both dependency entries together (lab-verified build passes).

### Pitfall 6: Home link loop
`CyberPageHeader` defaults `homeHref='/'` and `showHomeLink=true`; after D-11 `/` redirects back to `/numogram/`. Pass `showHomeLink={false}` in `NumogramClient` (Wave 2). The library component itself stays unchanged (it is part of the exported component library).

### Pitfall 7: `tsc` cannot enforce the engine boundary alone
`import React from 'react'` and `../../app/data/zones` type-check inside `engine/`; only ESLint catches them. Keep both, and keep `types: []` so `document`/`process`/`node:fs` fail in tsc.

### Pitfall 8: `no-restricted-imports` `regex` option does not exist in ESLint 8.57.1
Config validation error ("should NOT have additional properties"). Use `no-restricted-syntax` selectors `ImportDeclaration[source.value=/^[^.]/]` (and Export*/ImportExpression variants).

### Pitfall 9: `npm install`/`npm ci` runs `prepare`
It regenerates `dist/` (58 files) on every install and dirties the tracked tree until `dist/` is untracked. After D-10 this is harmless, but `check-clean-tree` after `build` must exclude ignored paths.

### Pitfall 10: CRLF working tree
174 tracked files are `i/lf w/crlf` (autocrlf=true). Adding `.gitattributes` does not change the index (verified: only `.gitattributes` staged after `git add --renormalize .`), and files re-check-out LF only when touched. Node scripts must write goldens with explicit `\n`; the golden files must be LF on disk or the manifest hashes differ between Windows and Linux. Add a check that fixtures contain no `\r`.

### Pitfall 11: The first `next dev` compile on Windows can be slow (not observed here)
Measured cold (`.next` deleted, Playwright `webServer` starting `next dev`): 13 s wall for a 2-state run including the first compile of `/numogram`; the warm 30-state capture took 52 s. Keep `webServer.timeout: 180_000` as a margin for slower CI machines and `reuseExistingServer` locally. Playwright terminated the `next dev` / `serve` child on Windows (port free afterwards). `[VERIFIED: lab]`

### Pitfall 12: `public/.DS_Store` ships in `out/`
Untrack and ignore `.DS_Store` (also `.claude/.DS_Store`).

### Pitfall 13: Settle detection races hydration (measured)
**What goes wrong:** the SSR HTML is always the default `original` state, and hydration plus the mount effects that apply the URL state land about 320 ms (dev) / 100 ms (static) after navigation, followed by one more re-render 50 ms / 15 ms later. A snapshot after `goto` alone mismatched the golden in 20/24 captures; waiting only for the viewBox mismatched 8/24 in dev (it is vacuous for `original`-layout states, which are 940 high in the SSR HTML); viewBox + hydrated without a stability window mismatched 8/24 in dev.
**Avoid:** expected viewBox height AND the `__reactFiber$` key on the `<svg>` AND 2 rAF AND 300 ms of unchanged normalized DOM (0/24 mismatches in dev and static). Do not wait for the intro layer (it never changes the SVG) and do not wait for a tween (none runs for URL-loaded state). Fixed sleeps and `networkidle` happened to pass but are timing heuristics. See "Playwright Capture Verification".

### Pitfall 14: `updateSnapshots: 'missing'` makes the capture run fail, and snapshot names are sanitized
**What goes wrong:** the first capture run exits 1 with `A snapshot doesn't exist at ..., writing actual.` for every golden (files ARE written); string names are rewritten (`a__b.svg.txt` becomes `a-b-svg.txt`); Playwright's own CLI default is `'missing'`, so a config without an explicit `'none'` would silently create goldens.
**Avoid:** expect exit 1 on the capture run and follow it with a `'none'` run that must exit 0; name snapshots `${layout}--${state}.txt` (hyphens and one extension survive) or use the array form; keep `updateSnapshots: 'none'` as the config default. `[VERIFIED: lab, Playwright 1.63.0]`

### Pitfall 15: esbuild-transpiled extractor breaks inside `page.evaluate`
**What goes wrong:** `page.evaluate(extractTree, ...)` fails with `ReferenceError: __name is not defined` when the function was transpiled by esbuild (`tsx`, Vitest, `tsup`), because `keepNames` injects a `__name(...)` helper; the same function works under Playwright's own test transform.
**Avoid:** call the extractor only from Playwright specs; when a script under `tsx` needs it, add `await page.addInitScript('window.__name = f => f')` or ship the extractor as a string. `[VERIFIED: lab]`

### scripts/page-weight.mjs (reader verified on `out/`; budget layer is straightforward)
```js

import { readFileSync, readdirSync, existsSync, writeFileSync } from 'node:fs'
import { gzipSync } from 'node:zlib'
import path from 'node:path'
const OUT = 'out'
const gz = b => gzipSync(b, { level: 9 }).length
function* walk(d) { for (const e of readdirSync(d, { withFileTypes: true })) { const p = path.join(d, e.name); e.isDirectory() ? yield* walk(p) : yield p } }
export function measure() {
  const routes = {}
  for (const f of walk(OUT)) {
    const rel = path.relative(OUT, f).split(path.sep).join('/')
```

### Normalizer that passed (`e2e/visual-dom.ts`, pure TS; the extractor runs in the page)

Design: the page returns a plain tree (`localName`, attributes, children; comments dropped, adjacent text nodes merged and whitespace-collapsed). The Node side drops `aria-*`, `data-*`, `role`, `tabindex`, sorts attributes alphabetically, canonicalizes `style` (declaration format, lowercase property, sorted) and rounds every number in geometry/paint attribute values to 3 decimals (`-0` becomes `0`; `#hex`, `url(#id)`, `id`, `class`, `href`, `font-family`, `filter`, `marker-*` and similar stay raw), then prints one element per line with 2-space indentation.

```ts
export interface RawNode { t: string; a: [string, string][]; c: (RawNode | string)[] }

/** Runs inside the browser (serialized by Playwright). Self-contained: no imports, no closures. */
export function extractTree(sel: string): RawNode {
  const roots = document.querySelectorAll(sel)
  if (roots.length !== 1) throw new Error(`expected exactly 1 ${sel}, found ${roots.length}`)
  const walk = (el: Element): RawNode => {
    const out: RawNode = { t: el.localName, a: [], c: [] }
    for (const n of el.getAttributeNames()) out.a.push([n, el.getAttribute(n) ?? ''])
    let text = ''
    const flush = () => { const s = text.replace(/\s+/g, ' ').trim(); if (s) out.c.push(s); text = '' }
    for (const ch of Array.from(el.childNodes)) {
      if (ch.nodeType === 3) text += ch.nodeValue ?? ''            // merge React's split text nodes
      else if (ch.nodeType === 1) { flush(); out.c.push(walk(ch as Element)) }
      // comments (React's <!-- --> markers) are ignored
    }
    flush()
    return out
  }
  return walk(roots[0]!)
}

const DROP_EXACT = new Set(['role', 'tabindex'])
const KEEP_RAW = new Set(['id', 'class', 'href', 'xlink:href', 'font-family', 'attributeName', 'in', 'in2', 'result', 'filter', 'clip-path', 'mask', 'marker-start', 'marker-mid', 'marker-end'])
export const isIgnoredAttr = (n: string) => n.startsWith('aria-') || n.startsWith('data-') || DROP_EXACT.has(n)

const round3 = (s: string) => { const r = Math.round(parseFloat(s) * 1000) / 1000; return Object.is(r, -0) ? '0' : String(r) }
const NUM_ANY = /-?(?:\d+\.?\d*|\.\d+)(?:e[+-]?\d+)?/gi                   // path data such as "M0,0.5L7,3"
const NUM_SPACED = /(?<![\w#.])-?(?:\d+\.?\d*|\.\d+)(?:e[+-]?\d+)?/gi      // style values: never touch #hex or identifiers

function canonStyle(v: string): string {
  return v.split(';').map(d => d.trim()).filter(Boolean).map(d => {
    const i = d.indexOf(':'); const p = d.slice(0, i).trim().toLowerCase(); const val = d.slice(i + 1).trim().replace(/\s+/g, ' ')
    return `${p}:${val.replace(NUM_SPACED, round3)}`
  }).sort().join(';')
}

export function canonAttr(name: string, value: string): string {
  if (name === 'style') return canonStyle(value)
  if (KEEP_RAW.has(name) || value.startsWith('#') || value.startsWith('url(')) return value
  return value.replace(NUM_ANY, round3)
}

export function normalizeTree(root: RawNode): string {
  const lines: string[] = []
  const emit = (n: RawNode, depth: number) => {
    const attrs = n.a.filter(([k]) => !isIgnoredAttr(k)).sort(([x], [y]) => (x < y ? -1 : x > y ? 1 : 0))
      .map(([k, v]) => ` ${k}="${canonAttr(k, v).replace(/"/g, '&quot;')}"`).join('')
    lines.push(`${'  '.repeat(depth)}<${n.t}${attrs}>`)
    for (const ch of n.c) typeof ch === 'string' ? lines.push(`${'  '.repeat(depth + 1)}#text ${JSON.stringify(ch)}`) : emit(ch, depth + 1)
  }
  emit(root, 0)
  return lines.join('\n') + '\n'
}

export const countElements = (text: string) => (text.match(/^ *</gm) || []).length   // DOM node count per golden (D-17)
```

### Playwright API facts (A6 resolved, Playwright 1.63.0)

- `updateSnapshots: 'missing'`: writes only absent goldens, **and the test that wrote one fails** with `A snapshot doesn't exist at <path>, writing actual.` A capture run therefore exits 1 (30 failures, 30 files written); re-running writes nothing and passes. It never overwrites a changed golden (a changed value still fails).
- `updateSnapshots: 'none'`: an absent golden fails (`A snapshot doesn't exist at <path>.`) and nothing is written; a changed value fails; nothing is overwritten.
- Playwright's CLI default without the config key is `'missing'` ("Running tests without the flag defaults to 'missing'"), so the config sets `'none'` explicitly; the config value is honored.
- Names: a string name is sanitized (`a__b.svg.txt` becomes `a-b-svg.txt`, `a_b.txt` becomes `a-b.txt`; `a--b.txt` and `ladder-zone-5.svg` keep their hyphens and extension). The array form `['sub', 'arr__c.txt']` is written verbatim. The spec uses `${layout}--${name}.txt`.
- `snapshotPathTemplate: '{testDir}/__golden__/{testFilePath}/{arg}{ext}'` yields `e2e/__golden__/golden.spec.ts/<layout>--<state>.txt`; there is no project or platform component, so `chromium-utc` and `chromium-ny` compare against the **same** files (runs 4 and 5 passed against goldens written by `chromium-utc`).
- `expect(text).toMatchSnapshot(name)` on a string is a plain text compare with a line diff on failure; the actual output goes to `test-results/<test>/<name>-actual.txt`.
- `webServer` with `reuseExistingServer: true` reused a manually started dev server, and started `npx serve out` / `npx next dev` itself (with `cwd`) when none was listening; the child was cleaned up after the run on Windows (port free afterwards).
- Git Bash mangles env values that start with `/` (`PATHN=/numogram` became `C:/Program Files/Git/numogram`): the same trap as Pitfall 3. Do not pass URL paths through env vars from Git Bash (or set `MSYS_NO_PATHCONV=1`).
